## 2. 配置结构

### 2.1 `PairConfig`

```rust
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct PairConfig {
    pub symbol: String,
    pub base_asset: String,
    pub quote_asset: String,
    pub quantity: Decimal,
}
```

### 2.2 `ObserverConfig` 彻底改造：`pairs` 为唯一真相源

**删除** `symbol`/`base_asset`/`quote_asset`/`quantity` 四个单数字段，只保留：

```rust
pub struct ObserverConfig {
    pub pairs: Vec<PairConfig>,   // 唯一交易对真相源，非空
    // ……其余全局字段不变……
}
```

```rust
impl ObserverConfig {
    /// 参与观察的币种对列表（空列表视为配置错误，见 validate）。
    pub fn effective_pairs(&self) -> &[PairConfig];
}
```

- **读取迁移**：`load`(TOML) 与 `load_from_json` 先探测旧格式（顶层存在 `symbol` 且无 `pairs` 键）：手工把顶层 `symbol`/`base_asset`/`quote_asset`/`quantity` 组装为单元素 `pairs` 再反序列化；新格式（含 `pairs`）直接反序列化。迁移仅发生在加载入口，`ObserverConfig` 结构本身无任何兼容残余字段。
- **保存**：`save_to_json` 始终输出 `pairs` 数组新格式；迁移后的配置再保存即为纯新格式。
- **校验**：`validate()` 要求 `pairs` 非空；每个 pair 的 symbol/base_asset/quote_asset 非空、quantity>0；拒绝重复 symbol。全局字段校验不变。
- **默认**：`default_config()` 生成 `pairs = [PairConfig { symbol: "BTCUSDT", … }]`。

## 3. observer 三入口逐币种化

### 3.1 公共运行单元

单币种全部逻辑（accounts → instruments → validate_pair → 双 feed 订阅 → 等待 VALID → 扫描/归档）收敛为逐币种单元，配置层面共享一个 HTTP client 与 Binance/Bybit `MarketDataVenue` 实例（venue 层已按 symbol 参数化，见 `binance_stream.rs` 行 114 等）。

### 3.2 `observe_once`

```rust
pub async fn observe_once(config: &ObserverConfig, archive_path: &Path)
    -> Result<Vec<ObservationRun>>;
```

对 `effective_pairs()` 每个 pair 独立执行完整单次观察（各自的 accounts/instruments/双 feed/等待/扫描），全部成功则各产生一个 `DecisionEvent` 经同一 `ArchiveWriter` 顺序落盘（事件已带 symbol，顺序写天然安全）；任一 pair 失败则整体返回 Err（与现状单对失败语义一致）。返回每币种一个 `ObservationRun`。

### 3.3 `observe_continuously`

```rust
pub async fn observe_continuously<F, S>(
    config: &ObserverConfig,
    archive_path: &Path,
    mut on_report: F,
    shutdown: S,
) -> Result<()>
where
    F: FnMut(&ScanReport),
    S: Future<Output = ()>;
```

保持**单循环 + 每 tick 逐对处理**（多币种数量 ≤32，串行扫描开销可忽略；ArchiveWriter 单写者安全，无锁）：

```
PairRun { pair, first: BookFeed, second: BookFeed,
          first_instrument, second_instrument, accounts: [AccountData; 2] }

启动：对每对 加载账户/品种/校验/订阅双 feed → 串行 wait_for_valid_pair（各自 stream_start_timeout，任一失败整体退出，与现状一致）
循环：tokio::select! {
    shutdown → break,
    account_ticker → 对每对按各自 symbol 重载 accounts,
    scan_ticker → 逐对：双 feed VALID → scan_current(pair) + on_report + submit(Decision)；
                  否则 submit(Health{feeds, skip_reason})
}
archive.finish()
```

- feed 状态是逐对的：单币种 feed 失效只产生该币种 Health，其余币种照常 VALID 扫描（F01-R03）。
- 账户数据按 symbol 独立加载（`load_account_data(&client, &pair.symbol, …)`，费率/准入逐币种），每对独立持有 `[AccountData; 2]`。
- `on_report(&ScanReport)` 回调签名不变；报告自带 symbol，前端按币种标识。

### 3.4 `run_reconnect_smoke`

```rust
pub async fn run_reconnect_smoke(config: &ObserverConfig)
    -> Result<Vec<PairReconnectSmoke>>;
pub struct PairReconnectSmoke { pub symbol: String, pub binance: BookFeedStatus, pub bybit: BookFeedStatus };
```

对 `effective_pairs()` 每对执行现有「订阅 → 强制重连 → 新代次恢复」烟测，结果按币种独立报告。

### 3.5 `scan_current` 逐币种化

```rust
fn scan_current(
    config: &ObserverConfig,
    pair: &PairConfig,
    first_status: &BookFeedStatus,
    second_status: &BookFeedStatus,
    first_instrument: &InstrumentSpec,
    second_instrument: &InstrumentSpec,
    accounts: &[AccountData; 2],
) -> Result<DecisionEvent>;
```

`quantity` 取 `pair.quantity`，strategy/freshness 取 config 全局字段（策略语义不变）。

## 4. 归档与事件

- `DecisionConfig` 序列化结构**不变**（symbol/base_asset/quote_asset/quantity 逐事件携带，天然多币种可区分）；新增 `DecisionConfig::from_pair(&PairConfig, &ObserverConfig)`（pair 提供四个交易对字段，config 提供 strategy/freshness）。原 `From<&ObserverConfig>` 保留（主对语义）。
- `DecisionEvent::capture` 签名改为接收 `pair: &PairConfig`（替代整个 config 的交易对部分）：
  `capture(pair, config, statuses, instruments, accounts, evaluated_at_ms, admission_rejections, report)`。
- `ScanReport`/`FeedVersion`/`ArchivedFeeVersion` 已带 symbol，无需变更。
- `SCHEMA_VERSION = 1` 不变；旧单币种归档可正常回放（事件级结构未动）。

## 6. 前端

- `commands.ts`：`ObserverConfig` 接口改为 `pairs: PairConfig[]`（删除 symbol/base_asset/quote_asset/quantity 顶层字段）并定义 `PairConfig` 类型；`DEFAULT_OBSERVER_CONFIG` 只含 `pairs: [BTCUSDT 主对]`。`observeOnce` 返回类型改数组。
- `types.ts`：`ConfigSummary` 改 `pairs: PairSummary[]`。
- `ConfigStrip.vue`：接收 `pairs`，展示 `首个币种 symbol`，多币种时附加 `+N 个币种` 标记（`pairs` 非空时兜底 `'—'`）。
- `AppFooter.vue`：展示首个币种 symbol 或 `市场`（pairs 派生）。
- `DetailPanel.vue`：扫描报告标题已带 `scanReport.symbol`（行 317），多币种观察结果显示最近报告或逐币种列表；报告数量统计随数组长度。
- `SettingsPage.vue`：删除主对四输入框，改为「币种列表」编辑区（每行 symbol/base_asset/quote_asset/quantity 四输入 + 删除按钮 + 添加按钮），保存时写入 `pairs`。

## 8. 失败关闭与边界

- 连续观察中单币种 feed 失效 → 该币种 Health 事件，不牵连其他币种；账户/品种加载失败仍整体拒绝（配置层问题）。
- 保持只读边界：`external_order_calls=0` 不变，不引入真实下单路径（F01-R07）。
- 多币种间价差（跨币种信号）明确不做，只做每币种两所间价差（与现状一致）。
