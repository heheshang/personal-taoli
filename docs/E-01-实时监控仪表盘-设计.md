# E-01 实时监控仪表盘：设计文档

文档状态：`in_progress`。实现实时监控仪表盘模块。

## 1. 模块边界

- `crates/core/src/dashboard.rs`：实时监控仪表盘核心模块，包含仪表盘数据和状态监控。

## 2. 仪表盘数据类型

| 类型 | 描述 | 使用场景 |
|---|---|---|
| SystemStatus | 系统状态 | 系统启动时间、运行时间、内存使用 |
| TradingStatus | 交易状态 | 订单数量、成交数量、收益 |
| MarketStatus | 市场状态 | 行情延迟、断档、深度 |
| RiskStatus | 风险状态 | 敞口、保证金使用率、事件 |

## 3. 仪表盘数据结构

```text
DashboardData {
    system: SystemStatus,
    trading: TradingStatus,
    market: MarketStatus,
    risk: RiskStatus,
    timestamp_ms: u64,
}

SystemStatus {
    uptime_seconds: u64,
    memory_usage_bytes: u64,
    cpu_usage_percent: f64,
    disk_usage_bytes: u64,
}

TradingStatus {
    order_count: i64,
    trade_count: i64,
    pnl: f64,
    active_orders: i64,
}

MarketStatus {
    market_data_latency_ms: f64,
    market_data_gap_seconds: f64,
    orderbook_depth: i64,
}

RiskStatus {
    exposure_usd: f64,
    margin_usage_percent: f64,
    risk_event_count: i64,
}
```

## 4. 仪表盘管理器设计

```text
DashboardManager {
    data: Arc<RwLock<DashboardData>>,
}

impl DashboardManager {
    pub fn new() -> Self;
    pub async fn update_system_status(&self, status: SystemStatus);
    pub async fn update_trading_status(&self, status: TradingStatus);
    pub async fn update_market_status(&self, status: MarketStatus);
    pub async fn update_risk_status(&self, status: RiskStatus);
    pub async fn get_dashboard_data(&self) -> DashboardData;
    pub async fn get_system_status(&self) -> SystemStatus;
    pub async fn get_trading_status(&self) -> TradingStatus;
    pub async fn get_market_status(&self) -> MarketStatus;
    pub async fn get_risk_status(&self) -> RiskStatus;
}
```

## 6. 失败关闭

- 仪表盘数据必须包含完整状态信息。
- 仪表盘更新必须支持异步操作。
- 仪表盘数据查询必须支持实时获取。
- 所有测试必须在隔离环境运行，不影响生产环境。

## 7. 接入命令

实时监控仪表盘可通过以下方式使用：

```text
// 创建管理器
let manager = DashboardManager::new();

// 更新状态
manager.update_system_status(system_status).await;
manager.update_trading_status(trading_status).await;

// 获取数据
let data = manager.get_dashboard_data().await;
```

## 8. 发布限制

实时监控仪表盘模块只用于隔离环境验证，不影响生产环境配置和运行。真实监控仪表盘需要独立的需求和审批流程。
