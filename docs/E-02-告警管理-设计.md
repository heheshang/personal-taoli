# E-02 告警管理：设计文档

文档状态：`in_progress`。实现告警管理模块。

## 1. 模块边界

- `crates/core/src/alert_manager.rs`：告警管理核心模块，包含告警创建、确认和解决。

## 2. 告警级别

| 级别 | 描述 | 处置 |
|---|---|---|
| Critical | P0: 无法确认的大额敞口、保证金危险、交易核心失联且有仓位、持久化失效 | 立即推送到至少两个独立通道；人工从原生交易终端接管 |
| High | P1: 未知订单超时、私有流中断、余额冲突、持续单场所故障 | 阻断对应新交易并尽快处理 |
| Medium | P2: 库存偏移、行情延迟升高、归档积压、收益估计误差变大 | 降级或计划处理 |
| Info | 信息: 正常启停、配置批准、日结、再平衡到账 | 保留审计，避免通知噪声 |

## 3. 告警状态

```text
Pending -> Acknowledged -> Resolved
                  |
                  v
               Ignored
```

## 4. 告警管理器设计

```text
AlertManager {
    alerts: Arc<RwLock<HashMap<String, AlertEvent>>>,
}

impl AlertManager {
    pub fn new() -> Self;
    pub async fn create_alert(&self, level: AlertLevel, title: String, message: String, source: String, labels: HashMap<String, String>, now_ms: u64) -> AlertEvent;
    pub async fn acknowledge_alert(&self, alert_id: &str, now_ms: u64) -> Result<AlertEvent>;
    pub async fn resolve_alert(&self, alert_id: &str, now_ms: u64) -> Result<AlertEvent>;
    pub async fn ignore_alert(&self, alert_id: &str, now_ms: u64) -> Result<AlertEvent>;
    pub async fn get_alerts(&self) -> Vec<AlertEvent>;
    pub async fn get_pending_alerts(&self) -> Vec<AlertEvent>;
    pub async fn get_alerts_by_level(&self, level: &AlertLevel) -> Vec<AlertEvent>;
    pub async fn get_alerts_by_status(&self, status: &AlertStatus) -> Vec<AlertEvent>;
    pub async fn clear_alerts(&self);
}
```

## 6. 失败关闭

- 告警创建必须包含完整信息。
- 告警状态变更必须记录时间戳。
- 告警查询必须支持按级别和状态过滤。
- 所有测试必须在隔离环境运行，不影响生产环境。

## 7. 接入命令

告警管理器可通过以下方式使用：

```text
// 创建管理器
let manager = AlertManager::new();

// 创建告警
let mut labels = HashMap::new();
labels.insert("component".to_string(), "system".to_string());
let alert = manager.create_alert(
    AlertLevel::Critical,
    "Test Alert".to_string(),
    "This is a test alert".to_string(),
    "test".to_string(),
    labels,
    1000,
).await;

// 确认告警
manager.acknowledge_alert(&alert.alert_id, 2000).await?;

// 解决告警
manager.resolve_alert(&alert.alert_id, 3000).await?;
```

## 8. 发布限制

告警管理模块只用于隔离环境验证，不影响生产环境配置和运行。真实告警管理需要独立的需求和审批流程。
