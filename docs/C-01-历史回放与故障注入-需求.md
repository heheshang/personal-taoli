# C-01 历史回放与故障注入：需求文档

文档状态：`in_progress`。本阶段实现历史回放验证和故障注入测试框架。

## 1. 目标

建立可重复的历史事件回放能力，在隔离环境验证系统在丢包、重复、断线、崩溃和数据库失效等故障场景下的行为。

## 2. 需求

| 编号 | 要求 | 验收结果 |
|---|---|---|
| C01-R01 | 支持从归档文件回放历史事件 | 可回放归档文件并生成ShadowReport |
| C01-R02 | 回放时验证数据一致性 | 检测到不一致时失败关闭 |
| C01-R03 | 支持多种故障类型注入 | 支持丢包、重复、断线、崩溃、数据库失效 |
| C01-R04 | 故障注入可配置可控制 | 支持启用/禁用、参数配置 |
| C01-R05 | 故障注入后验证恢复能力 | 检测恢复并验证数据完整性 |
| C01-R06 | 测试结果可追溯 | 生成结构化测试报告 |

## 3. 明确不做

- 不接入真实交易所进行故障测试。
- 不修改生产环境配置。
- 不执行真实故障（仅模拟）。
- 不影响系统正常运行。

## 4. 验证边界

```text
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
npm run build
cargo build --workspace --release
```

故障注入测试套件必须覆盖所有预定义故障类型，每个测试必须有明确的预期行为和结果验证。
