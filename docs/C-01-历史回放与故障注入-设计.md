# C-01 历史回放与故障注入：设计文档

文档状态：`in_progress`。实现故障注入测试框架。

## 1. 模块边界

- `crates/core/src/fault_injection.rs`：故障注入核心模块，包含故障类型定义、故障注入器和测试套件。
- `crates/core/src/archive/reader.rs`：历史回放模块（已有）。
- `crates/core/src/archive/report.rs`：回放报告生成（已有）。

## 2. 故障类型

| 故障类型 | 描述 | 触发方式 | 验证点 |
|---|---|---|---|
| PacketLoss | 丢包 | 随机概率 | 系统继续运行，数据完整性保持 |
| Duplicate | 重复消息 | 随机概率 | 系统去重，不产生重复处理 |
| Disconnect | 断线 | 外部触发 | 系统检测断线并自动重连 |
| Crash | 进程崩溃 | 外部触发 | 系统重启后恢复状态 |
| DatabaseFailure | 数据库失效 | 外部触发 | 系统检测数据库失效并降级运行 |

## 3. 故障注入器设计

```text
FaultInjector {
    fault_type: FaultType,
    enabled: bool,
}

impl FaultInjector {
    pub fn new(fault_type: FaultType) -> Self;
    pub fn disable(&mut self);
    pub fn enable(&mut self);
    pub fn should_trigger(&self) -> bool;
    pub fn duration(&self) -> Option<Duration>;
}
```

## 4. 测试套件设计

```text
FaultInjectionTestSuite {
    tests: Vec<FaultInjectionTest>,
}

struct FaultInjectionTest {
    name: String,
    fault_type: FaultType,
    expected_behavior: String,
}

impl FaultInjectionTestSuite {
    pub fn default() -> Self;
    pub async fn run_all(&self) -> Result<Vec<FaultInjectionResult>>;
    async fn run_test(&self, test: &FaultInjectionTest) -> Result<FaultInjectionResult>;
}
```

## 5. 测试结果结构

```text
FaultInjectionResult {
    fault_type: String,
    triggered: bool,
    duration_ms: Option<u64>,
    recovery_detected: bool,
    data_integrity_preserved: bool,
}
```

## 6. 失败关闭

- 故障注入器启用/禁用状态必须可控制。
- 故障触发必须基于配置的概率或外部信号。
- 测试结果必须包含恢复检测和数据完整性验证。
- 所有测试必须在隔离环境运行，不影响生产环境。

## 7. 接入命令

故障注入测试套件可通过以下方式调用：

```text
// 运行所有故障注入测试
let suite = FaultInjectionTestSuite::default();
let results = suite.run_all().await?;

// 运行单个测试
let injector = FaultInjector::new(FaultType::PacketLoss { rate: 0.1 });
let should_trigger = injector.should_trigger();
```

## 8. 发布限制

故障注入测试框架只用于隔离环境验证，不影响生产环境配置和运行。真实故障注入需要独立的需求和审批流程。
