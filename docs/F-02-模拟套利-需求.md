# F-02 模拟套利（真实场景仿真执行）：需求文档

文档状态：开发中（2026-09-09 立项建议）。立项编号建议为 F-02（阶段 F 生产准备第二个迭代，延续 F-01 多币种观察；§11 已预留 F-02 编号）；若所有者倾向独立编号（如 G-01）仅重命名文档与发布记录，无其他影响。

本迭代把「真实行情 → 决策」单向链路扩展为「真实行情 → 决策 → 模拟撮合 → PAPER 事实落库 → 仿真报告」闭环。**全程不产生任何真实或测试网订单**（PAPER/模拟适配器边界，`external_order_calls=0` 恒真），满足架构文档 §18.1 第 4 级「实时影子运行：真实行情和账户费率，不下实单」与 §18.2 模拟成交要求。

## 1. 目标

当前观察闭环在 `scan_current` 产出 `DecisionEvent` 后即止：accepted 的 `Opportunity` 只进归档与前端报告，没有任何后续执行语义。本迭代新增**模拟撮合引擎**：以决策事件携带的双方订单簿、仪器规格、费率为输入（真实行情快照，不编造），按 §18.2 的保守规则模拟双腿（跨所一买一卖）成交、时延、提交响应丢失与查询恢复，并把全部执行事实写入既有 PAPER 事实层（PAPER 计划/意图/成交/预留/执行事实），输出可序列化的仿真报告。连续观察模式下，每个 accepted 机会自动进入模拟闭环；命令层提供一次性烟测入口。

核心原则（不可丢弃）：**模拟成交价以最差侧成交价（deepest-swept worst price）加保守不利偏移为准，绝不「看到卖一就假设全量可买」**（§18.2「不能看到卖一就假设全量可买」）。

## 2. 需求

| 编号 | 要求 | 验收结果 |
|---|---|---|
| F02-R01 | 模拟引擎以 `ScanReport` 的 accepted 方向 + 决策事件携带的双方 `OrderBookSnapshot`/`InstrumentSpec`/费率版本为输入，逐档深档消费，不采用 VWAP 乐观价 | 模拟成交价≥买侧最差价（含不利偏移）、≤卖侧最差价（含不利偏移），报告记录逐档滑动量 |
| F02-R02 | 深度不足/盘口消失：按 `sweep` 语义逐档消费，深度不足时腿部分成交（按可得深度），完全无可用深度时该腿无成交并标记 scenario，不虚报容量 | 深度不足 → 部分成交数量=可得深度且报告含 `depth_shortfall` 标记；盘口耗尽 → 无成交、无 order fact 之外的虚构记录（AT-01） |
| F02-R03 | 竞争成交：可配置敌手占盘比例，每档有效数量按比例缩小（其余视为已被竞争者拿走），成交价向不利方向推移 | 配置占盘 bps 生效：同簿配置占盘=0 成交全量，占盘=10000 时无成交；中档比例下成交价劣于扫描最差价 |

| F02-R05 | 提交响应丢失：可配置 `submit → UNKNOWN` 概率与查询 `Found/NotFound` 概率；UNKNOWN 后按查询结果恢复或保持 UNKNOWN，不产生重复订单 | UNKNOWN 路径：`submit_result(Unknown)` → `query_result(Found)` 恢复成交，同一 `exchange_order_id`/`trade_id` 不重复入账；`NotFound` 保持 UNKNOWN 并记录（AT-05/AT-10） |

| F02-R08 | 仿真报告：每 run 输出可序列化报告（成交价/量、滑点 bps、手续费、净盈亏、scenario、时延采样值、UNKNOWN/查询标记、plan/账户 id、补偿决策），全程 `Decimal` 不转浮点 | 报告字段覆盖上述全部；前端可直接渲染；同一 run 数据库事实与报告多数值一致 |

## 3. 明确不做

- 不接入真实或测试网订单；`external_order_calls=0` 恒真；不解除 A-05（14 天影子窗口至 2026-09-22T09:52:14Z 评审）。
- 不做 maker 排队/撤改单模型（§18.2：未实现时不得展示可靠 maker 回测收益）；本迭代只模拟 taker 跨所双腿。
- 不拟合真实时延/滑点概率分布：本轮为配置区间均匀采样 + 保守不利侧假设（adverse_move_x 上限）与敏感性验证；真实网关时延分布采集与拟合属 F-03 真实接入评估。
- 不做 K 线回测（§18.1：不能只用 K 线回测短时订单簿套利）；模拟输入只有实时快照与决策事件。
- 不新增数据库表、不升 `SCHEMA_VERSION`（保持 4）；复用现有 PAPER 事实层。
- 不在设置页增加模拟配置编辑 UI：模拟配置来自 `observer.{toml,json}`，后端校验，前端仅展示。连续模拟的运行状态不进 `SessionController` 状态机（一次性 ff 事件队列，独立生命周期）。
- 不做跨机会资金共享模型：每个 run 独立 PAPER 账户与资金池（AT-11 的真实共享资金模型属真实接入语义，明确不在影子层模拟）。
- 不做基础资产计费残差模型（AT-02 的适配器级语义）：两腿费用统一以报价资产计入 `trade_facts.fee_amount`；基础资产计费换算与残差入账归真实接入迭代。
- 不改变 `scan_pair`/策略参数语义；不做多币种间价差。

## 4. 验收方法

### 4.1 §18.2 要求 → 本迭代承担

| §18.2 要求 | 本迭代实现 | 证据 |
|---|---|---|
| 按历史可见信息推进，不提前使用未来盘口 | 撮合只消费启动 run 时队列持有的快照与最新快照，无未来数据 | 撮合输入=快照克隆，代码审查 + 纯逻辑测试 |
| 非固定零时延 | 配置区间均匀采样（决策→提交、提交→成交回报） | 时延采样断言 + seed 复现测试 |
| 处理盘口消失、竞争成交、数量不足；不假设卖一全量可买 | 逐档 sweeper + adverse 偏移 + 敌手占盘 + 深度不足部分成交/拒绝 | smoke S2/S3/S4；AT-01 |
| 深度折扣/不利成交场景与敏感性分析 | adverse_move_x/competitor_take_x 配置可调，smoke 对比占盘 0 与全占 | smoke S3/S4 |
| 模拟成交只是估计，最终以真实成交校准 | 报告输出滑点 bps 与扫描最差价对比，累计滑点可评估 | run 报告 |

### 4.2 验收用例（合成簿 smoke，`run_simulation_smoke`）

| 编号 | 场景 | 必须观察到 | 对应 |
|---|---|---|---|
| S01 | 深度充足、无不利因素 | 双腿全量成交，成交价=最差档价，`scenario=Normal`，净盈亏≈扫描预期 | §18.2 基线 |
| S02 | 买侧深度只覆盖 60% 目标量 | 买腿部分成交（60%），卖腿按可得量成交，`depth_shortfall` 标记，敞口按 B-03 评估 | AT-01 |
| S03 | 敌手占盘 10000 bps（盘口全部消失） | 双腿无成交，`scenario=CompetedAway`，无任何虚构成交事实 | AT-01/AT-04 影子 |
| S04 | 敌手占盘中间比例 | 成交价劣于扫描最差价，买卖滑点 bps 为负向，净盈亏低于原估计 | §18.2 敏感性 |
| S05 | 初始注入余额小于目标量所需 | `reserve_plan` 拒绝（insufficient funds），报告 `Rejected`，无 order/execution 事实残留 | AT-11/AT-13 |
| S06 | UNKNOWN 提交 + 查询 Found | UNKNOWN → 查询恢复成交，订单不重复，trade 幂等（重复 record 忽略） | AT-05/AT-10 |
| S07 | 补偿预算超限 | `evaluate` 返回 `ManualRequired`，`execution_state=MANUAL_REQUIRED` | AT-07 |
| S08 | 同请求幂等复放 | 同 `request_id` 二次 `reserve_plan` 返回 `idempotent_replay=true`，事实不重复 | AT-12 |
| S09 | 运行边界 | 全场景 `external_order_calls == 0`；`schema_version == 4`；恢复检查（plan/order/execution 事实一致性）通过 | B 系列范式 |
