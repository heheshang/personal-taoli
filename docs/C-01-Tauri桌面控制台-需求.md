# C-01 Tauri 桌面控制台：需求文档

- 迭代编号：C-01
- 状态：`ready`
- 上游：A-03 实时订单簿、A-04 账户能力与费率、A-05 行情归档、B-01/B-02/B-03 PAPER 安全核心
- 目标：将现有 Rust 观察与 PAPER 运维操作迁移到 Tauri 桌面窗口，由 Vue + Element Plus + TypeScript 展示可观察结果

## 1. 用户可观察结果

1. 用户打开桌面应用后，看到当前安全模式、配置摘要、品种、数量、归档路径和两所连接端点。
2. 用户点击“加载账户状态”后，看到 Binance/Bybit 能力卡、只读权限、费率来源、加载时间、过期时间及准入拒绝原因；界面不显示 key、secret 或签名。
3. 用户点击“一次实时观测”后，Rust 等待两所公共订单簿同时 `VALID`，执行一次双向扫描，返回两所盘口状态、两个方向的 VWAP、成本、净收益、准入状态和拒绝原因，并归档该决策。
4. 用户点击“回放归档”后，看到回放记录数、在线/失效时长、重连、净收益分布、容量分布、拒绝原因、缺口和尾部样本。
5. 用户点击 PAPER 烟测后，看到 B-01/B-02/B-03 对应的数据库事实验证结果和 `external_order_calls=0`。
6. 任何 Rust command 错误均以统一失败响应展示，不把超时、未知、失效或缺少凭证显示为成功；失败响应包含稳定错误码、上下文和是否可重试。

## 2. 安全边界

- 桌面端只开放公共行情读取、只读账户元数据、归档回放和 PostgreSQL/PAPER 烟测。
- 不开放真实或测试网下单、撤单、补偿订单、提现、转账和自动策略执行。
- secret 由前端设置页掩码输入、保存为 JSON 配置文件，Rust 启动时读取并注入环境变量后使用；任何界面与日志均不展示明文。
- `COMPENSATION_PLANNED` 只能展示为计划事实，不得展示为已发送或已成交。
- 账户准入拒绝、行情非 `VALID`、实际费率不可用或过期时，界面必须保留拒绝原因。

## 3. 验收场景

| 编号 | 场景 | 必须观察到的结果 |
|---|---|---|
| C01-R01 | 启动桌面应用 | 显示 `READ_ONLY_AND_PAPER`，真实订单能力为关闭 |
| C01-R02 | 加载配置 | 显示配置摘要，不显示凭证值 |
| C01-R03 | 无凭证账户检查 | 返回能力卡和 observation-only 回退费率，显示准入拒绝 |
| C01-R04 | 一次实时观测 | 双所同时 `VALID` 后返回双向完整成本字段并写入归档 |
| C01-R05 | 行情同步失败 | 命令失败或状态非 `VALID`，不返回可执行机会 |
| C01-R06 | 归档回放 | 回放统计与 Rust 回放结果一致，损坏记录失败关闭 |
| C01-R07 | PAPER 烟测 | 对应报告可展示，外部订单调用数固定为 0 |
| C01-R08 | Rust 错误 | Element Plus 错误提示包含可行动上下文，不吞掉错误 |

## 4. 明确不做

- 不保留 CLI 参数作为产品操作入口；本轮将原 CLI 编排迁移为 Tauri command。
- 不实现自动持续观测后台任务、真实交易适配器、交易控制面、完整账务和对账。
- 不引入 Node 服务端、消息队列或新的策略。

## 5. 验收方法

- `npm run build`：构建 Vue + Element Plus + TypeScript 静态前端。
- `cargo build --workspace --release`：编译 Tauri Rust 应用。
- `cargo test --workspace`、`cargo fmt --all -- --check`、`cargo clippy --workspace --all-targets -- -D warnings`：回归领域逻辑和桌面命令。
- `cargo tauri dev` 或生成的桌面二进制：实际打开窗口，依次执行配置、账户、实时观测、回放和 PAPER 操作；环境缺少 PostgreSQL 时，PAPER 操作显示明确失败，不得伪造成功。
