## 4. 发布验证顺序

```bash
cargo fmt --all -- --check
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo run -p personal-taoli-observer --release -- --account-check --output json
```

真实账户凭证可用时，上线前还必须在受控终端执行同一账户检查，并人工核对：

1. `region_eligible_confirmed=true` 与实际所在地合法性一致；
2. `account_eligible_confirmed=true` 与实际账户状态一致；
3. `read_only=true`；
4. Binance 危险 scope 全部关闭，Bybit 无 `Withdraw`；
5. `actual_account_rate=true`；
6. symbol 与目标品种一致；
7. 加载/过期时间合理；
8. 输出和日志中无 key/secret。

该上线前步骤在发布环境尚未执行，不能从本地夹具结果推断真实账户已合格。

## 5. 发布证据

- 格式检查和项目测试通过。
- Clippy `--all-targets -- -D warnings` 通过。
- Binance 签名实现通过官方 documented HMAC 向量。
- 本地 HTTP 夹具验证 Binance commission 买卖分量组合及危险权限判定。
- 本地 HTTP 夹具验证 Bybit 请求 headers/query、`retCode` 错误和权限/费率解析。
- 费率 `now == expiry` 保持有效，`now > expiry` 产生拒绝原因。
- 无凭证 `--account-check --output json` 可运行：能力卡和配置回退费率可见，两所均明确拒绝实际费率不可用及资格未确认。
- 程序无订单入口；账户模式只调用权限和费率接口。

## 6. 未完成项与边界

以下不是 A-04 代码缺口，但仍是实盘前置条件：

- 在用户实际且合法的 Binance/Bybit 账户上验证地区/账户资格；
- 确认真实 API key 为只读且所需私有接口可用；
- 获取并人工核对目标 symbol 的真实账户费率；
- 根据生产安全政策决定是否把 `ip_restricted` 升级为硬门禁；
- 观察费率刷新在长期运行中的失败率和过期占比；该证据由 A-05 连续窗口承载。

## 7. 完成定义

A-04 可保持 `released`，当且仅当：

- A04-R01 至 A04-R09 行为继续成立；
- 配置回退费率永远不能被标记为实际费率；
- 权限未知、危险或实际费率过期时两个方向均拒绝；
- 公共观察不会因私有接口失败整体退出；
- 凭证不进入序列化结构、输出或归档；
- 文档不把确定性夹具验证误述为真实账户资格已通过；
- 程序仍无订单能力。
