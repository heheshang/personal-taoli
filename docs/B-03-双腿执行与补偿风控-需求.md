# B-03 双腿执行与补偿风控：需求文档

- 迭代编号：B-03
- 状态：`released`；实现仅覆盖 PAPER 双腿事实与补偿决策闭环
- 上游：B-01 PAPER 计划/资金预留/单写者，B-02 订单事实与 `UNKNOWN` 状态机
- 阶段门禁：A-05 连续影子观察仍独立 pending；本轮不得接入真实或测试网订单接口
- 运行边界：PostgreSQL 持久化执行事实；不发送订单、不撤单、不自动补偿成交

## 1. 目标与可观察结果

系统必须在两腿订单事实可查询后，按实际两腿累计成交量计算确定的数量差和未匹配敞口；当敞口与补偿成本均在批准预算内时生成可审计的补偿计划，当任一硬限额超出或成交量违反计划时进入 `MANUAL_REQUIRED`。重启后从数据库恢复同一状态，不把未知状态伪造为已匹配或已对冲。

PAPER 烟测必须可观察地证明：部分成交会生成预算内补偿决定；两腿数量匹配会完成计划；超出补偿预算会升级人工；重启加载保留人工状态；整个路径的外部订单调用数为 0。

## 2. 输入与状态不变量

- 一个执行计划只属于一个 `account_id + instrument_id` 域，并由 B-01 的单写者保护。
- `target_quantity > 0`；`max_unmatched_exposure >= 0`；`compensation_budget >= 0`。
- 每次评估传入的两腿累计成交量不可小于数据库已确认值，且不得超过计划数量。
- `unmatched_quantity = abs(leg_a_filled - leg_b_filled)`。
- `unmatched_exposure = unmatched_quantity × exposure_per_unit`。
- 本次估计补偿成本为 `unmatched_quantity × compensation_cost_per_unit`。
- 所有数量、价格、敞口和成本使用 PostgreSQL `NUMERIC` 与 Rust `Decimal`；不得先转浮点数。
- 每次状态变化先在同一事务写不可变执行事件与补偿决定，再更新当前快照；版本号严格递增。
- `COMPLETED` 和 `MANUAL_REQUIRED` 是终态；终态禁止再次评估。

状态集合：

```text
PLANNED -> COMPENSATION_PLANNED -> COMPLETED
PLANNED -> COMPLETED
PLANNED -> MANUAL_REQUIRED
```

`RUNNING` 为数据库允许的中间状态，当前 PAPER 编排不把它作为自动发送许可。`MANUAL_REQUIRED` 表示自动处置停止，既不表示敞口已消失，也不表示计划盈利。

## 3. 验收场景

| 编号 | 场景 | 结果 |
|---|---|---|
| B03-R01 | 两腿均为零成交或累计成交相同且不超过目标 | 写入完成事件，状态为 `COMPLETED`，补偿数量为零 |
| B03-R02 | 一腿部分成交、另一腿零成交，敞口和成本均在预算内 | 写入补偿决定，状态为 `COMPENSATION_PLANNED`，数量等于差额 |
| B03-R03 | 后续事实使两腿累计成交相等 | 写入完成事件，状态转为 `COMPLETED`，重启可读取闭合快照 |
| B03-R04 | 未匹配敞口超过硬限额 | 状态为 `MANUAL_REQUIRED`，保留差额和原因，不伪造中性 |
| B03-R05 | 累计补偿成本超过预算 | 状态为 `MANUAL_REQUIRED`，不得继续计划自动补偿 |
| B03-R06 | 任一腿成交量超过目标或成交量倒退 | 超量进入人工；倒退直接拒绝本次事实更新，不覆盖数据库快照 |
| B03-R07 | 进程在评估提交后重启 | 从 `execution_facts` 恢复状态、数量、敞口、预算消耗和版本；不调用外部订单 |
| B03-R08 | 同一账户—品种并发执行者竞争 | 第二个执行者无法取得 B-03 域锁，已有事实不被并发覆盖 |
| B03-R09 | 数据库写入失败或状态枚举未知 | 失败关闭；不以内存状态继续、不发送订单 |

## 4. 明确不做

- 不连接 Binance、Bybit 或任何真实/测试网私有 API。
- 不实现真实下单、撤单、补偿成交、价格保护、重试、限频或私有流恢复。
- 不把 `COMPENSATION_PLANNED` 解释为补偿订单已提交或已成交。
- 不在本轮实现完整账务、费用入账、余额对账、dust 台账或人工控制面；这些属于 B-04。
- 不解除 A-05 连续观察门槛，不授予交易权限，不改变只读/模拟安全边界。

## 5. 失败关闭与发布条件

以下任一情况必须停止自动处置并保留人工调查证据：数据库不可写、计划不存在或不属于当前域、累计成交倒退、成交超出目标、预算或敞口边界无法计算、状态值未知、事件版本冲突、锁获取失败。任何网络超时只能由 B-02 先形成订单事实，B-03 不根据超时猜测成交结果。

B-03 不能发布为真实执行能力，除非后续迭代另行完成适配器权限、调用前耐久化、UNKNOWN 恢复、私有事件、账务、对账、补偿订单风险和 P0 故障验收。
