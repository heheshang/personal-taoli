# A-05 行情归档与连续影子统计：需求文档

## 2. 目标与用户可观察结果

系统应把每次可执行扫描所依赖的行情、品种规格、账户费率、决策配置、准入原因和计算结果保存为可独立回放的证据；无法扫描时保存双方行情健康状态及跳过原因。维护者应能在不连接交易所、不读取当前配置的情况下复算历史决策，并得到连续观察期间的时长、失效、重连、机会、容量、拒绝原因和数据缺口报告。

## 3. 明确不做

- 不提交、撤销或查询订单，不申请或使用交易权限。
- 不证明策略盈利，不以发现正价差或运行满 14 天替代经济可行性评审。
- 不把账户回退费率描述为实际费率；缺少真实账户元数据时继续失败关闭。
- 不在本轮引入 PostgreSQL、消息队列服务、分布式采集、对象存储或自动清理任务。
- `raw_retention_days` 仅作为归档元数据记录；本轮不实现保留期删除。
- 不保证归档记录具备密码学防篡改性；回放只验证内部重算一致性和结构/顺序约束。

### 4.1 A05-R06 样本计数规则

- **正净收益候选样本**：某方向的 `expected_net_profit > 0`。账户资格或实际费率缺失仍可令该方向 `accepted=false`；候选样本不等于可交易机会。
- **独立事件段**：按归档顺序分别跟踪两个买卖方向。正值从非正值转入时开始一个事件段；若与同方向上一条正值样本相隔至少 30 秒，也开始一个新事件段。一个持续正值事件段只计一次。
- **数量门槛**：两个方向合计至少 100 个独立正净收益候选事件段，并分别报告各方向数量。方向评估总数、连续 2 秒采样数和 `accepted_opportunities` 均不能替代该计数。
- **故障门槛**：正式窗口内 Binance 与 Bybit 的自然重连计数各至少增加 1，且至少出现一次 `HealthEvent` 后恢复为双方 `VALID` 的决策事件。人工执行 `--reconnect-smoke` 不计入。
- **不足处理**：到达 14 天但任一门槛不足时继续 `in_progress`；不得缩短 30 秒间隔、降低成本/新鲜度/准入阈值或把人工故障注入计为自然样本。

## 5. 场景需求

### 5.1 正常场景

1. 双方本地簿均为 `VALID` 时，每个扫描周期产生一条决策事件。
2. 决策事件保存本次重算所需的全部输入；后续配置、盘口或账户费率变化不得改变历史回放结果。
3. 连续模式收到 Ctrl-C 或 SIGTERM 后停止接收新事件，排空归档队列并正常退出。
4. 维护者可在采集仍运行时执行回放；回放只读取启动瞬间的文件长度，不等待后续追加。

### 5.2 边界场景

1. 回放时末行正在写入且没有换行：忽略该未完成尾部并报告字节数，不把它当作完整损坏记录。
2. 启动写入器时发现无换行尾部：截断残片，并在缺口日志记录修复字节数。
3. 多个进程运行形成多个 `run_id`：每个运行内部的 `ordinal` 必须严格递增；重连计数按运行增量汇总，不能跨运行取全局最大值。
4. 未知拒绝原文：完整原文保留在归档中，报告统一聚合为 `other_rejection_reason`，避免报告键空间无界。
5. 无决策事件：收益和容量分布为空，而不是伪造零收益样本。

### 5.3 失败关闭场景

1. 任一行情不是 `VALID` 或缺少快照：不得生成决策，改写健康事件并保存跳过原因。
2. schema 不支持、完整换行记录不是合法 JSON、事件时间倒退、运行内序号重复/回退、配置摘要不一致、盘口身份不一致或重算结果不一致：整个回放失败，不输出“通过”报告。
3. 归档队列满：扫描继续，但丢弃区间必须记录首末事件、时间和数量。
4. 归档文件不可写：扫描继续，写入器尝试恢复归档文件，并把受影响事件记录到缺口日志；缺口日志也不可写时必须输出错误，不能声称归档完整。
5. 真实账户资格、只读权限或实际费率不可用：即使行情与归档正常，所有机会仍保持拒绝。

### 5.4 恢复场景

1. 优雅停止：写线程排空并刷盘，后续回放应无未完成尾字节。
2. 进程崩溃留下半条记录：重启只移除最后的无换行残片，保留此前完整记录，并审计修复动作。
3. 完整换行记录损坏：禁止自动截断或跳过，要求人工保全原文件后调查。
4. 进程自动重启：产生新的 `run_id`；正式评审必须说明停机时长和重启原因，不得仅以首末事件跨度计入连续在线时长。

## 6. 非功能与安全要求

- 金额、数量、价格和费率保持十进制定点数，不经二进制浮点数。
- 归档采用追加写 NDJSON；原始归档和 `.gaps.ndjson` 缺口日志均不得进入版本控制。
- 主行情路径只做非阻塞 `try_send`；磁盘写入由单一后台线程串行完成。
- 回放内存随收益/容量样本数增长，但不保存全部归档记录；拒绝原因键空间必须由固定类别约束。
- 归档不得包含 API secret、签名、完整私有请求头或账户敏感响应。
- 默认配置无真实凭证且资格确认均为 `false`，系统只有只读公共行情能力。

## 7. 可重复验收

```bash
cargo fmt --all -- --check
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo run -p personal-taoli-observer --release -- --once --output json
cargo run -p personal-taoli-observer --release -- --reconnect-smoke
cargo run -p personal-taoli-observer --release -- --replay data/archive/a05-shadow-20260908.ndjson --output json
```

验收解释：

- 前三项必须成功且无警告。
- `--once` 必须输出两个方向及完整成本、账户版本、准入决定和拒绝原因；当前无真实账户费率时 `REJECT` 是正确结果。
- `--reconnect-smoke` 必须显示两所代次增加并恢复 `VALID`。
- `--replay` 必须返回 `replayed_without_mismatch=true`；窗口发布还要求 `gap_records=0`、`dropped_events=0`、未完成尾字节为 0，或对任何非零值完成书面调查。
- A05-R06 的最终验收还必须执行《A-05 连续影子观察运行与评审说明》，不能只运行上述命令。
