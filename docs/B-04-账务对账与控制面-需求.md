# B-04 账务、对账与控制面：需求文档

文档状态：`verified`。本迭代只实现 PostgreSQL/PAPER 事实与控制意图，不连接交易所私有接口，不发送订单。

## 1. 目标

建立可审计的多资产复式账务、余额快照与对账差异事实，并为人工控制操作提供带授权主体、幂等键、过期时间和审计日志的持久化命令边界。

## 2. 需求

| 编号 | 要求 | 验收结果 |
|---|---|---|
| B04-R01 | 账务事件必须按资产借贷平衡 | 不平衡事件拒绝；平衡事件及明细持久化 |
| B04-R02 | 业务键重放必须幂等且禁止内容漂移 | 同一业务键返回原事件；冲突事件拒绝 |
| B04-R03 | 已写账务和余额快照不可变 | UPDATE/DELETE 由数据库触发器拒绝 |
| B04-R04 | 记录外部余额快照并校验完整性 | total/free/locked 非负且 free+locked 不超过 total |
| B04-R05 | 对账结果必须区分匹配、缺失、延迟和冲突 | 差异类别与运行状态持久化 |
| B04-R06 | 对账失败不得以内存结果替代数据库事实 | 事务失败不返回已提交报告 |
| B04-R07 | 控制动作必须绑定 actor、scope、request_id 和过期时间 | 缺失字段、非法时间或非法动作失败关闭 |
| B04-R08 | 控制请求必须幂等且审计 | request_id 重放不生成重复命令；动作和结果进入审计日志 |
| B04-R09 | 过期控制命令不得执行 | 过期命令保持 EXPIRED；不调用订单适配器 |

## 3. 明确不做

- 不接入 Binance、Bybit 或任何真实/测试网私有 API。
- 不执行真实暂停、撤单、减仓、恢复或停止动作；控制模块只记录意图和结果。
- 不自动补拉真实流水、不释放 B-01 资金预留、不结算真实费用。
- 不将 `external_order_calls=0` 解释为真实订单安全证明。

## 4. 验证边界

```text
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
npm run build
cargo build --workspace --release
```

桌面控制台 `ACCOUNTING CONTROL SMOKE`（`run_accounting_control_smoke`）必须覆盖平衡/不平衡、账务幂等和不可变历史；匹配/缺失/冲突对账；控制命令幂等、完成和过期不执行。A-05 连续观察门槛仍是进入真实订单适配器的唯一前置条件。
