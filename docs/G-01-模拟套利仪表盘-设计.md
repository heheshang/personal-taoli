# G-01 模拟套利仪表盘（独立页面）：设计文档

文档状态：开发中（2026-09-09）。配套需求文档 `docs/G-01-模拟套利仪表盘-需求.md`；本文件锁定模块边界、数据契约、关键决策与风险。核心原则：**展示层只读**（查询不走领域单写者锁、页面零写路径、`external_order_calls=0` 恒真）；**报告专属值以投影表落库为只读冗余**，事实单一真相源始终是既有 PAPER fact 表；**全部金额 `Decimal`（serde-str 已全局启用，前后端传输即字符串）**；**全部图表手写 SVG**。

## 2. 数据契约

### 2.1 `simulation_runs` 投影表（新增，migration 0005）


要点：
- **不可变触发器**：投影为只读冗余，禁 UPDATE/DELETE（与 `audit_events`/`balance_snapshots` 同一防护风格）。
- **`external_order_calls` 恒 0**：INSERT 契约硬编码 0（引擎无外呼路径），schema CHECK 仅在 `>= 0` 兜底负值；不把 `= 0` 写死进永久 schema，避免阻碍 F-03 真实接入评估的约束演进。
- `report` JSONB 整存 `SimulationRunReport`（其 serde `rename_all="snake_case"`，`scenario` 枚举为 SCREAMING_SNAKE_CASE，直接透传序列化）。
- 枚举 CHECK 值域与 Rust 枚举名称一致（NORMAL/DEPTH_SHORTFALL/COMPETED_AWAY/REJECTED），INSERT 时由 Rust 端映射。
- 幂等：`ON CONFLICT(run_id) DO NOTHING`（run_id 全局唯一，replay 不覆盖首跑投影）。

### 2.2 余额历史：复用 `balance_snapshots`（`source='SIMULATION'`）

不新建余额表。引擎在 run 内写 **每 run 两账户 × 三节点** 快照，`source='SIMULATION'`，`completeness='COMPLETE'`：

| 节点 | 时机 | 语义（模拟结算后视图） |
|---|---|---|
| `fund` | 两账户 `set_paper_balance` 注入后 | `total=free=initial_quote`（买所=""账户 quote 资产） / `=initial_base`（卖所账户 base 资产） |
| `filled` | 双腿 `record_trade` 完成、`evaluate` 前 | 买所账户：`initial_quote − buy_cost − buy_fee`；卖所账户：`initial_base − sold_quantity`（卖出交割） |
| `evaluated` | `evaluate` 后 | 与 `filled` 同值（补偿为现金评估、不落地）；曲线第三点，语义「评估后无资金变动」 |

快照行：`snapshot_id = sim-snap-f02-{ts}-{pid}-{dir}-{node}-{asset}`（8 段固定，`{ts}`/`{pid}` 即 run_id 后两段），`account_id = f02-account-{ts}-{pid}-{dir}`，`venue`=买/卖所名，`asset`=quote/base，`observed_at_ms` 取各节点时刻（三节点互异，天然满足 `(account_id,venue,asset,observed_at_ms)` 唯一约束），`total=free`（模拟无交易所锁定，locked=0）。node 不落列，由 `parse_sim_snapshot_id` 从 id 第 6 段解析（fund/filled/evaluated）。

**推演说明（重要）**：`record_trade` 不更新 `paper_balances`（PAPER 语义：余额同步由对账驱动，成交不写影子余额）→ 若快照读现值，三点将仅反映「注入 − 预留锁定」，无成交信息量。故快照存储**模拟结算后视图**（注入额 ± 成交额 − 费用，全 `Decimal` 显式计算），`source='SIMULATION'` 与对账快照（`balance_snapshots` 仅对账时写）严格区分，曲线呈现真实资金流出/流入方向。

### 2.3 run 归属解析（活动日志/审计流）

`audit_events` 的 `aggregate_id`/`correlation_id` 形如 `f02-{ts}-{pid}-plan-{dir}`；run_id = `f02-{ts}-{pid}`。前缀解析：`split('-')` 取前 3 段 join（run_id 三段固定且 ts/pid 无 `-`）。

## 3. 查询 API（`simulation_query.rs`，只读）

连接策略：`simulation_query::open(database_url)` 开**独立只读连接**，查询包在单个只读事务（`BEGIN READ ONLY`）内多表读取，保证快照一致性；**不经 `DomainConnection::acquire`**（避免读竞争写）。查询命令入口先 `migrate(database_url)`（老库 version 4 → 自动升 5）再 `verify_schema`。

| 命令 | 入参 | 返回 |
|---|---|---|
| `get_simulation_overview` | — | `SimulationOverview` |
| `get_simulation_runs` | `limit, offset, symbol?, scenario?` | `SimulationRunsPage` |
| `get_simulation_run_detail` | `run_id` | `SimulationRunDetail` |

山脊分组：按时间桶（默认**按日**；桶内点数 < 8 时自动降级为跨日合并——单日低成本 run 场景避免空桶），`bucket = executed_at_ms / day_ms` 聚合 `simulated_net_profit` 数组，SQL 返回 `(bucket, nets)` 由 Rust 端分组，前端 SVG kernel 密度曲线。

## 4. 关键决策（评审点）

### D1 投影表而非「从 fact 表实时聚合」
report 专属值（scenario/净盈亏/滑点 bps/时延/补偿决策/UNKNOWN 标记/warnings）只存在 report 对象与 tracing 日志，未落任何 fact 表；从既有表无法重建这些值。决策：新投影表整存 report JSONB + 关键检索列（§2.1）。事实单一真相源不变；投影为只读冗余，引擎只增两处无害钩子。

### D2 引擎钩子位置与失败语义
- **钩子 1**：run 出口（Success/Rejected/IdempotentReplay 全分支）`INSERT ... ON CONFLICT(run_id) DO NOTHING`。INSERT 失败 → **bail**（run 报告即产物，报告持久化失败 = run 失败；与事实层写入失败失败关闭一致）。
- **钩子 2**：三节点余额快照（§2.2）。快照写失败 → **仅 `warnings` 记录 + tracing**，不 bail（快照是展示层冗余投影，不绑架 run 语义）。
- 幂等 re-run：`reserve_plan` 幂等 replay 分支同样写投影行（`idempotent_replay=true`）——机会历史完整显示 replay 事件。

### D3 查询层只读 + 读连接独立
查询不经 `DomainConnection::acquire`（避免与写路径竞争单写者锁）；独立连接 + `BEGIN READ ONLY` 事务保证一次请求内多表快照一致。查询失败 → `api_fail(ErrorCode::SimulationError)`（复用既有错误路径），页面显示错误态可重试。

### D4 命令面
三个命令（§3）注册进 `invoke_handler`；`commands/simulation_query.rs` 与烟测命令 `commands/simulation.rs` 分文件；dto.rs 直接透传 core 结构（`serde-str` 全局生效，Decimal→字符串）。`get_simulation_runs` 带 `limit≤200` 上限防大页。

### D5 余额曲线 = 模拟结算后视图（§2.2）
`record_trade` 不写影子余额 → 现值曲线无成交信息量。快照存储结算后推演值（注入 − 成交 − 费用），实现对「账户变化图」可读的资金轨迹；`source='SIMULATION'` 保证与对账快照隔离。

### D6 山脊图 = 报告投影聚合，非实时统计
按日桶分组净盈亏数组（§3），前端 SVG kernel density + 中位数标记；无第三方库。为诚实呈现「低净盈亏采样少」的形态，桶内点数 <8 自动合并跨日。（不拟合真实分布——需求 §3。）

### D7 流转图 = 模板 + 真实事件点亮
静态状态机模板（EVALUATED → COMPENSATION_DECIDED → {COMPLETED | MANUAL_ESCALATED}）与资金流模板（注入 → 预留 → 双腿成交 → 补偿评估）；`execution_events`+`audit_events` 聚合最近 run 的真实事件序列点亮节点 + 计数。事件表不可变 → 溯源可信。

### D8 前端接线
`SidebarNav.pages` 增「模拟套利」项（SVG 图标）；`App.vue` 增 `simulation` 区块（`v-show` 与既有五页并列）；**仅当 activePage === 'simulation' 时**每 10s 轮询 `get_simulation_overview`（离开页面停止定时器，避免后台空转）；「运行一次烟测」按钮复用 `run_simulation_smoke_command`（成功后刷新全部板块）；配置摘要复用既有 `get_observer_config`（不重复造轮子）。全部图表组件沿用 HistoryChart/RidgePanel 的 SVG 视觉体系。

## 5. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 投影表写入失败连锁 run 失败 | 失败关闭语义（与事实层一致）+ `ON CONFLICT` 幂等；余额快照失败仅降级告警（冗余投影不绑架 run） |
| 余额快照与对账快照混淆 | `source='SIMULATION'` 专值；对账快照 `source` 值域不受影响（source 为自由文本列，无 CHECK） |
| `external_order_calls=0` 兜底 | INSERT 契约硬编码 0（引擎无外呼路径）+ 既有 smoke 单测断言；schema 仅兜负值；页面「0 次真实调用」徽章 |
| 报表大表增长（每 run 一行 JSONB + 每 run 6 快照行） | 关键列索引（时钟/symbol/scenario）；列表 SQL 不读 `report` 列（`SimulationRunRow` 主营列查询）；分页必带 `limit ≤ 200` |
| 山脊桶采样稀疏 | 桶内 <8 点自动跨日合并 + 空态提示；不拟合分布（诚实呈现） |
| 引擎 hook 意外改成交语义 | 钩子全在 run 出口/明确节点：仅 INSERT 投影与快照，不触碰撮合/决策/时延路径；F-02 smoke 单测回归把关（含 `external_order_calls` 断言） |
| 读连接与写连接并发 | PostgreSQL MVCC + `BEGIN READ ONLY` 快照隔离；无锁竞争设计（D3） |
| 旧库（version 4）升级 | 任何 G-01 命令入口先 `migrate`（执行 0001–0005 + `verify_schema(5)`）；0005 幂等（`IF NOT EXISTS`/`DROP TRIGGER IF EXISTS`/`ON CONFLICT`）；0001–0004 零改动 |
| 页面轮询空转 | 仅 activePage==='simulation' 时轮询；离开即停；错误不弹窗、显示重试态 |
