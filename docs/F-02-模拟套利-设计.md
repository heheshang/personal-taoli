# F-02 模拟套利（真实场景仿真执行）：设计文档

文档状态：开发中（2026-09-09）。配套需求文档 `docs/F-02-模拟套利-需求.md`；本文件锁定模块边界、数据契约、关键决策与风险。核心原则：**模拟执行强制走既有 PostgreSQL PAPER 事实层（AIDLC §4.3 单一真相源），不引入第二真相源**；**模拟成交价以最差侧价格加保守不利偏移为准，绝不用 VWAP 乐观价**。

## 1. 模块边界

```
crates/core/src/simulation.rs          ← 新增：纯逻辑撮合 + 报告 + 烟测
crates/core/src/config.rs               ← ObserverConfig 增 simulation 字段 + validate
crates/core/src/observer.rs             ← 连续模式：accepted 机会 → 队列 → 引擎（改动最小）
src-tauri/src/commands/simulation.rs    ← 新增：run_simulation_smoke 命令
src-tauri/src/commands/dto.rs           ← SimulationSmokeResult DTO 变体
src-tauri/src/error.rs                  ← SimulationError 变体
src/components/DetailPanel.vue          ← 模拟报告展示 + 一键运行入口
src/App.vue / src/commands.ts           ← 命令注册与 TS 类型
```

数据流（单 run）：

```
DecisionEvent { books, instruments, fees, report }
  → SimulationEngine::submit(run_request)          [observer 队列 / 命令层直接]
  → set_paper_balance ×2                           [专属账户初始注入]
  → PaperCore.reserve_plan                          [预留互斥、余额校验]
  → ExecutionCore.initialize_plan
  → OrderCore.ensure_intent ×2 → submit_started ×2 → submit_result ×2
      （配置概率走 SubmitResult::Unknown → query_result Found/NotFound）
  → simulate_leg 逐档撮合（输入=事件携带双 book + SimulationConfig + SimRng）
  → OrderCore.record_trade（每腿按成交 chunk，幂等 trade_id）
  → ExecutionCore.evaluate（双腿已成交数量 + 敞口/补偿成本）
  → SimulationRunReport
```

`external_order_calls` 在本迭代无任何出处——simulation.rs 不接触 venue/HTTP 层，恒为 0（烟测断言）。

## 2. 数据契约（无新表，`SCHEMA_VERSION=4` 不动）

所有 ID 以 `f02-{unix_timestamp_ms}-{pid}` 为 run 命名空间，全局唯一：

| 实体 | 命名 | 落点 |
|---|---|---|
| PAPER 账户 | `sim-{stamp}-{dir}`（dir=a\|b 方向） | `paper_balances`/各 fact 表 `account_id` |
| instrument_id | `{symbol}:f02:{stamp}-{dir}` | 各 fact 表 `instrument_id` |
| request/plan | `f02-{stamp}-{dir}-request/-plan` | `execution_plans(request_id,plan_id)` |
| opportunity_id | `f02-{stamp}-{dir}-opportunity` | `execution_plans.opportunity_id` |
| intents/attempts/orders | `f02-{stamp}-{dir}-{buy,sell}-...` | `order_intents`/`order_facts` |
| reservations | `f02-{stamp}-{dir}-{quote,base}` | `fund_reservations` |
| exchange_order_id | `f02-sim-{stamp}-{dir}-{leg}` | `order_facts`（模拟身份，非交易所单） |
| trade_id | `f02-trade-{stamp}-{dir}-{leg}-{seq}` | `trade_facts` |

预留语义：`reserve_plan` 后 `fund_reservations` 恒为 `LOCAL_RESERVED`（PAPER 层无释放 API，见 §5 风险）。per-run 独立账户 → 余额初始注入一次、回流置换永不发生，规避 `set_paper_balance` 的「活动预留拒绝替换」约束。

`strategy_config_version` 与 B-03 的 `b03-smoke-v1` 风格一致，取 `f02-sim-v1`（文档化常量）。

## 3. SimulationConfig（`[simulation]` TOML 表，全字段 serde default + validate）

| 字段 | 默认 | 语义 |
|---|---|---|
| `enabled` | `false` | 连续模式是否接入模拟引擎 |
| `seed` | `0` | 0=随机种子；非 0=确定性可复现 |
| `initial_quote_balance` | `"10000"` | 每 run 买腿注入的报价资产（USDT） |
| `initial_base_balance` | `"2"` | 每 run 卖腿注入的基础资产 |
| `decision_to_submit_ms_min/max` | `50/400` | 决策→提交时延采样区间（闭区间） |
| `fill_latency_ms_min/max` | `20/250` | 提交→成交回报时延采样区间 |
| `adverse_move_bps` | `"15"` | 成交价不利偏移（0–10000）；买侧加价×、卖侧减价× |
| `competitor_take_bps` | `"200"` | 敌手占盘比例（0–10000），每档有效量×（1-占比） |
| `unknown_submit_probability_bps` | `"300"` | 提交落入 `SubmitResult::Unknown` 的概率 |
| `query_found_probability_bps` | `"6000"` | UNKNOWN 后首次查询 Found 的概率 |
| `max_unmatched_exposure` | `"100"` | 传入 `initialize_plan`/`evaluate` 的敞口预算（USDT·unit） |
| `compensation_budget` | `"20"` | 补偿预算（USDT·unit） |
| `compensation_markup_bps` | `"30"` | 补偿成本 = 双腿最优中间价×(1+markup) per unit |

默认值取向：不利侧（adverse 15bps、占盘 2%）使「模拟收益」系统性低于扫描乐观估计——符合 §18.2「深度折扣/不利成交场景」与「不能假设按卖一全量可买」。

## 4. 关键决策（评审点）

### D1 模拟执行强制走 PostgreSQL（唯一真相源）
既有 B 系列烟测/命令全部以 `database_url` 驱动 PAPER 事实层；模拟成交若走「内存+归档第二真相源」会产生两份并行事实、崩溃后无法重建、审计断链。决策：simulation.rs 全部状态迁移复用 `DomainConnection`/`PaperCore`/`OrderCore`/`ExecutionCore`；缺 `TAOLI_DATABASE_URL` 或连接失败 → 失败关闭（命令层返回 `SimulationError`，连续模式该机会标记失败不拖垮观察循环）。**本决策征求所有者确认。**

### D2 成交价模型（§18.2 核心）
- 撮合输入：run 启动时持有的事件克隆快照（决策点可见信息），逐档消费至目标量或深度耗尽。
- 每档有效数量 = 档量 × (1 − competitor_take_bps/10000)，按 `quantity_step` 圆整。
- 档价施加 adverse 偏移（买腿 `price × (1+adverse)`，卖腿 `price × (1−adverse)`）。
- 深度不足：按可得深度部分成交 + `depth_shortfall` 标记；可得量为 0 → `CompetedAway` 无成交。
- 圆整后 < `min_quantity` 的腿 → 该腿拒绝（整腿无成交，计入报告 warnings）。
- 不引用 VWAP/扫描乐观价做成交价；扫描最差价仅作滑点对比基线。

### D3 时延采样与确定性
`SimRng`：内部实现 splitmix64（约 15 行，无外部依赖，跨平台确定性；避免引入 rand 依赖）。`seed=0` 时以 `unix_timestamp_ms()` 播种并回写报告；非 0 时全链路（占盘、偏移、时延、UNKNOWN/查询分支）线性消费同一 RNG 流 → 同 seed 完全复现。配置区间上均匀整数采样，`min<=max` 由 validate 保证。

### D4 observer 接入（连续模式）
`on_report` 是同步 `FnMut(&ScanReport)`，改签名会波及 `session.rs` 调用方。决策：**不改签名**。新增 `SimulationEngine::spawn(config)` 启动一个异步消费者（mpsc 队列 + 独立 tokio task，串行单写者）；observer 在 `on_report` 之后把 `DecisionEvent` 克隆推入队列。消费者：若队列积压 >1 则跳帧只处理最新机会（模拟「决策延迟 + 行情漂移」），执行完整 DB run。引擎生命周期独立于 SessionController；引擎错误记入 run 报告/日志，观察主循环不受影响。`SimulationEngine` 提供 `run_once(event, config) -> Report` 供命令层 smoke/一次性路径复用同一撮合核心。

### D5 每机会独立 PAPER 账户与资金池
见 §2。规避预留释放缺口与余额替换冲突；AT-11 影子语义 = 单 run 内双腿共用账户的预留互斥（`lock_and_check_balances` 原生保证）。跨机会共享资金的真实语义明确不做。

### D6 明确不做（需求 §3 摘要）
真实订单、maker 模型、真实分布拟合、K 线回测、SCHEMA 升级、前端设置页编辑、跨机会资金共享、基础资产计费残差。

## 5. 风险与缓解

| 风险 | 缓解 |
|---|---|
| PAPER 层无预留释放/计划关闭 API：长期连续模拟会累积 `RESERVED` 计划与 `LOCAL_RESERVED` 预留行 | 每 run 独立账户隔离；行增长记录为已知运维成本；真实接入前必须实现计划关闭/释放（剩余风险，进发布记录） |
| 撮合基于快照，决策与成交之间簿已更新 | 撮合按配置区间时延推迟执行 + adverse/占盘偏移兜底（§18.2「处理盘口消失」）；不假设快照仍有效，深度以撮合时刻消费结果为准 |
| 模拟余额是影子资产，初始注入额远大于实际需求 | `initial_*_balance` 为显式配置项；S05 校验余额不足时全部状态回滚 |
| 连续模式队列积压导致事实延迟 | 跳帧策略：只执行最新机会，积压不堆积；报告 `warnings` 记录跳帧次数 |
| UNKNOWN 路径依赖 B-02 状态机 | 复用 `SubmitResult::Unknown`/`QueryResult` 既有语义零新增状态 |
| 两方向同时 accepted | 每方向独立 run 独立账户；报告 `direction` 字段区分 `{buy_venue}→{sell_venue}` |
