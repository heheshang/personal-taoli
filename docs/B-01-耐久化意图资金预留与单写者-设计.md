# B-01 耐久化意图、资金预留与单写者：设计文档

## 1. 设计结论

B-01 新增独立的 PAPER 持久化核心，不把数据库调用塞进当前只读行情扫描热路径。核心使用 `tokio-postgres` 和一个版本化 SQL migration。每个实例用独立 PostgreSQL 会话持有账户—品种 advisory lock；业务事务依靠余额行锁、唯一约束和审计事件完成可恢复写入。

本轮没有订单适配器。`order_intents.submission_status` 只能是 `NOT_SENT`。这不是占位行为，而是 B-01 的安全边界：证明外部副作用发生前的责任状态已经耐久化。

## 2. 模块边界

- `crates/core/src/paper.rs`
  - PAPER 请求、腿、预留和恢复快照领域类型。
  - 输入规范化、十进制和唯一性校验、请求 SHA-256 摘要。
  - PostgreSQL 连接、migration、单写者租约、模拟余额和原子预留事务。
  - PAPER 端到端烟测编排；不引用交易所下单模块。
- `crates/core/migrations/0001_paper_core.sql`
  - schema 版本、模拟余额、执行计划、风险决定、订单意图、资金预留和不可变审计事件。
- `src-tauri/src/commands/paper.rs`
  - `run_paper_smoke("B01")` Tauri 运维入口；数据库 URL 从环境变量读取。
  - 该命令在创建任何 HTTP 客户端或交易所适配器前返回。

## 3. 唯一数据契约

### 3.1 `ReservePlanRequest`

请求包含：

- `request_id`：业务幂等键；永久绑定第一次规范化请求摘要。
- `plan_id`：内部计划 ID。
- `account_id`、`instrument_id`：单写者与活跃计划执行域。
- `opportunity_id`、`strategy_config_version`：批准依据。
- `target_quantity`、`max_unmatched_exposure`：十进制风险输入。
- 两条 `OrderIntentInput`：独立 `intent_id`、`leg_id`、`attempt_id`、`client_order_id`、场所、方向、数量和限价。
- 一个或多个 `ReservationInput`：独立 ID、场所、资产和正金额。

摘要在校验后对稳定排序的腿和预留进行 JSON 序列化并计算 SHA-256。同幂等键改变任何经济字段都会得到不同摘要并被拒绝。

### 3.2 `RecoveredPlan`

恢复结果包含计划状态与摘要、两腿 `NOT_SENT` 意图、全部 `LOCAL_RESERVED` 预留。它只表达数据库事实，不带“可以发送”标志。

## 4. PostgreSQL 模型

- `schema_migrations(version, applied_at_ms)`
- `paper_balances(account_id, venue, asset, observed_total, observed_free, local_reserved, observed_at_ms)`
- `execution_plans(plan_id, request_id, request_digest, account_id, instrument_id, opportunity_id, strategy_config_version, target_quantity, max_unmatched_exposure, state, created_at_ms)`
- `risk_decisions(plan_id, approved, input_digest, decided_at_ms)`
- `order_intents(intent_id, plan_id, leg_id, attempt_id, client_order_id, venue, side, quantity, limit_price, submission_status, created_at_ms)`
- `fund_reservations(reservation_id, plan_id, account_id, venue, asset, amount, state, created_at_ms)`
- `audit_events(event_id, aggregate_id, aggregate_version, event_type, correlation_id, causation_id, occurred_at_ms, payload)`

关键约束：

- 同一 `request_id` 唯一，同一内部 client order ID 永不复用。
- 同一账户—品种仅一个 `RESERVED` 活跃计划。
- `local_reserved` 非负且不超过 PAPER `observed_free`。
- B-01 意图状态数据库约束为 `NOT_SENT`，预留状态为 `LOCAL_RESERVED`。
- 审计表通过触发器拒绝 UPDATE/DELETE。

## 5. 单写者与并发

执行域键为 `account_id + NUL + instrument_id` 的 SHA-256 前 64 位，映射到 PostgreSQL session advisory lock。连接取得 `pg_try_advisory_lock` 后才构造 `PaperCore`；失败即拒绝。锁随数据库会话断开释放，不表示允许自动切换到实盘。

不同品种可以各自持锁，但可能共享余额。预留事务按 `(venue, asset)` 排序后执行 `SELECT ... FOR UPDATE`，因此余额是跨品种并发的最终仲裁点。事务完成前不调用任何外部系统。

## 6. 原子事务

`reserve_plan` 顺序：

1. 本地校验并规范化请求，生成摘要。
2. 开启事务，首先取得基于 `request_id` 的事务 advisory lock。
3. 查询已有幂等记录；摘要相同则提交只读事务并返回原计划，摘要不同则失败。
4. 锁定所有 PAPER 余额行，检查存在性和 `observed_free - local_reserved`。
5. 写 `execution_plans`、`risk_decisions`。
6. 增加余额 `local_reserved`，写 `fund_reservations`。
7. 写两条 `NOT_SENT` 意图。
8. 写 `PlanReserved` 审计事件。
9. 提交事务并读取恢复快照。

任一步失败均回滚。外部 API 不在事务内，本轮也不存在外部 API 调用。

## 7. 崩溃与恢复

连接中断后，已提交事务完整保留，未提交事务由 PostgreSQL 回滚，session advisory lock 自动释放。新实例重新取得同域锁后调用 `recover_active_plans`：

- 返回 `RESERVED` 计划；
- 保留 `LOCAL_RESERVED`；
- 保留两腿 `NOT_SENT`；
- 不自动生成新 ID、不释放资金、不模拟成交。

B-02 必须在此基础上增加提交前状态转换、`IN_FLIGHT/ACCEPTED/DEFINITELY_REJECTED/UNKNOWN` 和调查逻辑。

## 8. 失败关闭与安全

- 数据库不可写、锁资格丢失或 schema 不匹配：禁止新 PAPER 计划。
- SQL 错误不降级到内存预留。
- 模拟余额只能由明确 PAPER 初始化函数写入；存在活跃预留时不能覆盖快照。
- 输出仅含业务 ID、状态和计数，不输出数据库 URL。
- 当前真实凭证加载和公共行情观察路径不依赖 PostgreSQL，行为保持不变。

## 9. 验收映射

| 需求 | 实现 | 验证 |
|---|---|---|
| B01-R01 | migration 与 `migrate` | 临时 PostgreSQL schema 查询 |
| B01-R02 | `PaperCore::acquire` | 同域双连接锁竞争与断开再获取 |
| B01-R03 | `reserve_plan` 单事务 | 成功跨表恢复；余额不足后无计划 |
| B01-R04 | 余额 `FOR UPDATE` | 不同品种并发竞争一份余额 |
| B01-R05 | 请求事务锁、摘要和唯一键 | 相同请求重放、冲突摘要拒绝 |
| B01-R06 | `recover_active_plans` | 关闭原连接后新实例恢复 |
| B01-R07 | 审计表与 JSON PAPER 输出 | 查询事件并检查输出字段 |

## 10. 迁移与删除

新增表名明确属于 B-01/PAPER 可验证边界；不替换 A-05 NDJSON 行情归档。没有旧持久化执行路径需要兼容或保留。未来真实余额模型必须新增一致快照与 exchange-locked 覆盖依据，不得直接把 `paper_balances` 改名后用于 LIVE。
