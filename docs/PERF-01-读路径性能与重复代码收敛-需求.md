# PERF-01 读路径性能与重复代码收敛：需求文档

文档状态：实现与验证已完成，待所有者确认（2026-09-10）。立项编号 **PERF-01**：与 `DB-01`、`UI-01` 同为**段外特批的横切迭代**（不占用 A–G 业务阶段编号，§11 下一轮唯一业务入口不变）。DB-01 完成了连接层池化，但只保证「连接复用」这一条；池化之后暴露出的读路径重复劳动、缺失索引与重复代码不在 DB-01 范围内，本迭代收口这一层。

**流程偏差声明（必须记录）**：本迭代的需求确认、设计评审与实现在同一会话内连续完成——AI 先交付代码审计报告（H/M/L 分级问题与证据 + 6 步建议执行顺序），所有者以「进行」确认按该顺序执行；执行中 AI 将 M3 降级为独立立项项、主动撤回 M7，两项偏离均在交付时说明但**未获所有者逐项复核**（完整对应表见 §5）。因此需求/设计/任务三份文档系**事后补正**，其内容与已交付代码逐条对应。按手册 §5.5，人工门禁（需求确认、设计评审、发布签收）中**仅「按建议顺序执行」经所有者口头确认**，其余待所有者逐项复核；本迭代不得在签收前标记 `released`。

## 1. 目标

DB-01 把连接层换成 sqlx 池之后，实库（`taoli-postgres`，55432）上仍存在四类可测的浪费，且互相叠加：

1. **每次查询都重跑全部迁移**：G-01 仪表盘按 10s 轮询，而 `get_simulation_overview` / `get_simulation_run_detail` 每次入口都调 `migrate()`——即借连接、取会话级 advisory 锁、用 `raw_sql` 顺序执行六份迁移全文（含 plpgsql 函数与触发器 DDL）、`verify_schema`、释放锁。这是每 10s 一次的纯重复 DDL。
2. **只读路径没有可用索引**：`audit_events`（只追加、不可变）、`trade_facts`、`execution_events`、`order_action_facts`、`balance_snapshots` 被 G-01 只读层反复扫描，但五份迁移只建了 6 个非主键索引，且没有一个能用在这些查询上。实库实测 `SET enable_seqscan=off` 后仍回落 Seq Scan，可判定「不存在可用索引」。
3. **无界读取**：累计曲线与山脊图按 `simulation_runs` 全表取回，行数随 run 单调增长，而前端只按像素渲染。
4. **同一逻辑多份实现**：行情解析函数在 4 个 venue 文件里复制了 6 份；`LevelUpdate` 有两个字段完全相同的定义；流转图有两条逐字相同的 SQL 且其中一条的语义是错的。

本迭代的目标是把上述四类问题收敛到可复现证据支撑的状态，**不改变任何业务语义、不新增写路径、不解除 A-05 影子窗口**。

## 2. 需求

| 编号 | 要求 | 验收结果 |
|---|---|---|
| PERF01-R01 | 就绪库单点：迁移与 schema 校验每个 `database_url` 在**进程内只执行一次**，之后所有调用命中缓存；迁移语义（单会话 advisory 锁、`raw_sql` 整份执行、幂等）逐字不变 | 同进程内两次 `get_simulation_overview` 的耗时差异可测（就近冷启动 vs 稳态）；`schema_migrations` 行数不因重复调用增长；跨进程重跑仍幂等 |
| PERF01-R02 | 读路径索引：为 G-01 只读层实际发出的五类查询补索引（`audit_events` 的 `aggregate_id` / `correlation_id` 前缀与 `occurred_at_ms`、`trade_facts(intent_id, occurred_at_ms)`、`balance_snapshots(source, observed_at_ms)`），纯增量、无表结构变更 | `SET enable_seqscan=off` 下对应的 `EXPLAIN` 由 Seq Scan 变为 Index Scan；`SCHEMA_VERSION` 5→6 且旧库自动升级；0001–0005 逐字不动 |
| PERF01-R03 | 累计曲线有界 + 服务端前缀和：曲线数据由服务端用窗口函数一次算出，并限定最近 N 个 run；前端不再做累计加法 | 返回点数 ≤ 上限；`executed_at_ms` 升序且前缀和单调；前端无 `parseFloat` 累加 |
| PERF01-R04 | 山脊有界：山脊取数限定最近 N 个 run | 返回样本点数 ≤ 上限；桶数与稀疏合并语义不变 |
| PERF01-R05 | 流转聚合：六个计数由 2 条查询产出（原为 6 条），且 `filled_runs` 必须反映**真实双腿成交**而非 `COMPLETED` 事件数 | `filled_runs` 与 `simulation_runs` 中 `bought_quantity>0 AND sold_quantity>0` 的行数一致；与 `completed_runs` 相互独立（实库上两者不相等） |
| PERF01-R06 | 单 run 详情：同表三次往返合并为一次；投影列清单在列表与详情两处**共用同一常量**，消除列清单漂移 | 详情返回的字段数与列表一致且 `report` 全文完整；缺行仍失败关闭 |
| PERF01-R07 | 前端合约过滤：过滤选项来自观察配置的 `pairs[].symbol`，其值域必须与 `simulation_runs.symbol` 的存储值一致 | 选中任一项均返回非空结果；配置中全部交易对均出现在下拉；不再出现带斜杠的字面量 |
| PERF01-R08 | 前端累计曲线：直接消费后端前缀和，不做浮点累加 | 曲线数值与后端字段一致；无 `parseFloat` 累加路径 |
| PERF01-R09 | 前端山脊重算成本：密度曲线不得随样本数线性放大 `Math.exp` 调用；不得对可能很大的数组使用展开运算符求极值 | 桶内样本数增长时重算成本只与分箱数相关；极端样本数下不抛 `RangeError` |
| PERF01-R10 | 行情热路径零浪费：本地簿每次增量更新不得构造并立即丢弃快照；同一解析逻辑全仓只有一份实现；`LevelUpdate` 只有一处定义 | 每事件不再产生被丢弃的快照分配；`grep` 全仓无重复定义；交叉盘/空边拒绝行为不变 |
| PERF01-R11 | 生命周期：模拟引擎的 worker 任务在观察循环用 `?` 提前返回时也不得存活 | 已知的早退路径不再泄漏任务（有 `Drop` 兜底） |
| PERF01-R12 | 配置加载：新格式配置不得被解析两遍 | 新格式路径上旧格式迁移函数不做完整 `Value` 解析 |

## 3. 正常、边界、失败与恢复场景

| 场景 | 输入 | 必须观察到 |
|---|---|---|
| 正常 | 空库首次启动 | 迁移执行一次、`schema_migrations` 含 1–6、`verify_schema` 通过；随后每 10s 轮询不再触发迁移 |
| 正常 | 已有库（version 5）升级 | 任一读入口触发 0006；版本升至 6；0001–0005 不重复施加 DDL 效果之外的语义 |
| 边界 | run 数远超曲线/山脊上限 | 返回点数被截断到上限；曲线仍按时间升序、前缀和单调；山脊桶内 `n` 与实际取回样本一致 |
| 边界 | 桶内样本极多 | 山脊重算不随样本数线性放大；不抛 `RangeError` |
| 边界 | 配置含 8 个交易对 | 下拉 8 项且每项都能过滤出结果 |
| 失败 | 只读查询内试图写 | PostgreSQL 拒绝；事务进入 aborted 态并整体上抛（DB-01 既有语义不变） |
| 失败 | 详情查询 `run_id` 不存在 | 返回 Err（失败关闭），不返回空结构 |
| 失败 | 库不可达 / URL 为空 | 失败关闭，不静默降级 |
| 恢复 | 跨进程重启 | 重新执行一次迁移并命中幂等；`schema_migrations` 行数不变 |
| 恢复 | 观察循环异常早退 | 模拟引擎 worker 不残留 |

## 4. 明确不做

- **不删除也不接线 16 个无生产调用点的模块**（`alert`/`alert_manager`/`backup`/`backup_strategy`/`dashboard`/`fault_injection`/`fencing`/`health`/`metrics`/`notification`/`operations`/`performance`/`rpo_rto`/`runbook`/`runbook_manager`/`system_health`，合计 6304 行、132 个测试）。这是 E 阶段脚手架，删除或接入命令面属产品决策；**其中若干模块内含只增不删的无界容器（`performance.rs`、`system_health.rs`、`notification.rs`、`alert_manager.rs`），接线前必须先补淘汰策略，否则即内存泄漏**。本迭代只在设计文档记录该事实与前置条件。
- **不改 `BookFeedStatus` 的 `venue`/`symbol` 为 `Arc<str>`**（原审计列为 MED，已由 AI 撤回）：实测该路径约 80 事件/秒 × 2 个约 7 字节分配 ≈ 8 µs/s，跨 6 个文件的改动不划算。记录为「已知但不成比例」。
- **不拆分 `DetailPanel.vue`、不重整概览页静态装饰组件、不为冒烟报告补 TS 判别联合**：均为需产品取舍的展示层决策。
- 不改变任何准入/撮合/补偿/账务语义；不新增真实或测试网订单路径；`external_order_calls=0` 恒真。
- 不改动 0001–0005 迁移文件、不改不可变触发器、不改领域单写者锁语义。
- 不做 A-05 14 天影子窗口相关任何变更。
- 不引入第三方图表库或性能分析依赖。
