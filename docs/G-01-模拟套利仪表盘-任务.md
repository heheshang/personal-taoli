## 1. 实现顺序

### 1.1 迁移：db.rs + 0005

- 文件：`crates/core/src/db.rs`
- `SCHEMA_VERSION` 4 → **5**；新增 `const MIGRATION_0005: &str = include_str!("../migrations/0005_simulation_runs.sql");`；`migrate()` 依序追加执行 0005（位置：0004 之后）；0001–0004 常量与文件**零改动**。
- `verify_schema` 不动（断言 `schema_migrations.max(version) == SCHEMA_VERSION` 的既有逻辑自动覆盖 5）。
- 文件：`crates/core/migrations/0005_simulation_runs.sql`（新增）
  - `CREATE TABLE IF NOT EXISTS simulation_runs (...)`：DDL 见设计 §2.1（run_id PK、报告关键列 + `report JSONB`；`external_order_calls BIGINT NOT NULL DEFAULT 0 CHECK (external_order_calls >= 0 AND external_order_calls = 0)`；枚举 CHECK 值域 NORMAL/DEPTH_SHORTFALL/COMPETED_AWAY/REJECTED、NO_ACTION/COMPENSATION_PLANNED/MANUAL_REQUIRED、PLANNED/RUNNING/COMPENSATION_PLANNED/COMPLETED/MANUAL_REQUIRED）。
  - 三索引：`simulation_runs_clock_idx (executed_at_ms DESC)`、`simulation_runs_symbol_idx (symbol, executed_at_ms DESC)`、`simulation_runs_scenario_idx (scenario, executed_at_ms DESC)`。
  - 不可变触发器 `simulation_runs_immutable`（`BEFORE UPDATE OR DELETE` RAISE EXCEPTION；`DROP TRIGGER IF EXISTS` + `CREATE OR REPLACE FUNCTION` 幂等）。
  - 末尾 `INSERT INTO schema_migrations(version, applied_at_ms) VALUES (5, ...) ON CONFLICT DO NOTHING;`（沿用 0001–0004 模式）。

### 1.2 引擎钩子：simulation.rs

- 文件：`crates/core/src/simulation.rs`（态：有 F-02 未提交改动；只添加、不改撮合路径）
- run 出口统一路径（Success / Rejected / IdempotentReplay 三分支经同一函数）：
  - `persist_simulation_run(database_url, &report) -> Result<()>`：`INSERT INTO simulation_runs(...) VALUES($1..$n) ON CONFLICT(run_id) DO NOTHING`；**INSERT 失败 → bail**（设计 D2）。键值映射：`scenario`/`compensation_decision`/`execution_state` Rust 枚举 → DB 字符串（与 0005 CHECK 值域一致）；金额全部 `Decimal`（db-postgres/IEEE 参数绑定，验证：net profit 允许负数）。
  - Rejected run：`quantity`/`scanned_net_profit` 等按报告字段取（若有缺省值零填充），`rejection_reason` 非空；`executed_at_ms`/`evaluated_at_ms` 取报告值。
  - `external_order_calls` 恒 0（结构体字段不存在则硬编码 0；CHECK 约束兜底）。
- 余额三节点快照（设计 §2.2）：
  - `snapshot_balances(database_url, &report, stamp) -> Result<()>`：每 run 两账户 × {fund, filled, evaluated} 六行 INSERT `balance_snapshots`（snapshot_id=`sim-snap-{stamp}-{dir}-{node}`，source=`'SIMULATION'`，completeness=`'COMPLETE'`，total=free、locked=0，venue/asset 按账户方向，observed_at_ms 各节点时刻）。
  - 结算后视图（设计 D5）显式计算：fund = 注入额；filled（买所 quote 账户）= `initial_quote − bought_quantity×buy_avg_price − buy_fee`、（卖所 base 账户）= `initial_base − sold_quantity`；evaluated = filled 同值。全程 Decimal。
  - **快照写失败 → warnings 追加 + tracing::warn，不 bail**（设计 D2）。
- 钩子调用点：`run_simulation_run` 内 `evaluate` 返回后（Success 与 Rejected 均出）→ snapshot → persist → return report。确认快照三个时刻的可用数据：fund 在注入后立即记录（此时 report 尚未组装——改为在注入后先写 fund 节点，filled/evaluated 等 report 组装后同写；三节点总是全写六行，fund 节点的 observed_at_ms 记录注入时刻）。
- 纯逻辑测试（`#[cfg(test)]`，不进 DB）：
  - `persist 映射`：report → 行键值映射表正确（枚举字符串、金额、缺口零填充）。
  - `结算后余额推演`：fund/filled/evaluated 三节点值（Decimal 精确断言）。
  - `run_id 前缀解析`（§2.3 split 前 3 段）→（解析函数若放 query 模块则测试随之）。

### 1.3 查询模块：simulation_query.rs（新增）

- 文件：`crates/core/src/simulation_query.rs` + `crates/core/src/lib.rs` `mod simulation_query;`（pub use 类型）。
- `open(database_url) -> Result<QueryConn>`：独立 tokio_postgres 连接（不经 `DomainConnection::acquire`）。
- 一次请求内 `BEGIN READ ONLY` 只读事务包装查询函数：
  - `total_runs / total_success / total_net_profit / scanned_net_profit / profit_runs / by_scenario`（GROUP BY scenario）。
  - `recent_runs(limit=20)`（**不 SELECT report 列**）。
  - `list_runs(limit, offset, symbol?, scenario?) -> (Vec<SimulationRunRow>, total)`：动态 WHERE（参数化），`limit ≤ 200` 强制；ORDER BY executed_at_ms DESC。
  - `run_detail(run_id) -> SimulationRunDetail`：run 行 + `report` JSONB 全文 + `order_intents`（LEFT JOIN order_facts + order_action_facts 汇总）+ `trade_facts`（该 run 前缀意图过滤）+ `execution_events`（plan_id 前缀）+ `audit_events`（aggregate_id/correlation_id 前缀）+ `balances`（snapshot_id 前缀）+ `activity`（最近 50 条 audit，`f02-` 前缀，Rust 端 run_id 三段解析）。
  - `ridge(bucket_ms) -> Vec<RidgeBucket>`：`SELECT (executed_at_ms / bucket_ms) AS bucket, simulated_net_profit FROM simulation_runs WHERE scenario <> 'REJECTED' ORDER BY ...`，Rust 端分组为 `nets: Vec<Decimal>`；桶内点数 < 8 时合并跨日桶（设计 D6）。
  - `account_balances`：`paper_balances` 中 `account_id LIKE 'f02-account-%'` 现值，按账户/资产。
- `pub async fn fetch_simulation_overview(database_url) -> Result<SimulationOverview>` 等三命令入口：**先 `migrate()` 再 `verify_schema`**（老库自动升级，需求 G01-R10）。
- 测试：`#[cfg(test)]` 纯逻辑（前缀解析、桶分组/合并映射），不依赖 DB。
