# G-02 模拟 run 来源判别：需求文档

文档状态：实现与验证已完成，待所有者确认（2026-09-10）。立项编号 **G-02**（阶段 G 后续，沿用手册 §11 已预告的「G-02 后续可视化/运维」编号）。

**触发来源（真实使用缺陷）**：所有者观察运行中的桌面应用，看到 `F-02 simulation: run f02-… start symbol=BTCUSDT`，而自己聚焦的是 ETH，遂判断「日志与选择不符」。排查结论**不是**选择未生效，而是三件事叠加：

1. 该 run 来自**合成簿烟测探针**（`run_simulation_smoke`），不是实时市场模拟。全库 620 条 run 的 `buy_venue` 恒为 `s01-buy`…`s07-sell`，实时 run 数为 0。
2. 探针的 symbol 是夹具常量 `"BTCUSDT"`（`simulation.rs` 的 `smoke_event`），与当前观察的币对无关。
3. 实时模拟从未产生任何 run——8000 条 decision 中 `accepted` 数量为 0，因为准入按设计失败关闭（凭证未配置、Bybit 资格未确认、实际费率 observation-only、名义金额低于下限）。

真正的问题是 **①：仪表盘把探针产物与市场仿真结果混在一起呈现**，既无来源列也无界面标注，所有者因此被误导。

**流程偏差声明**：需求与实现由同一会话内的一次问答确定（所有者从三段式选项中选择「两项都做」+「模拟页保持独立过滤」），三份文档系事后补正。人工门禁中设计评审与发布签收待所有者完成。

## 1. 目标

让「这条 run 是合成簿探针还是实时观察」在**数据层可查询、在界面层不可误读**，并把探针的合成属性在启动日志中显著声明。

## 2. 需求

| 编号 | 要求 | 验收结果 |
|---|---|---|
| G02-R01 | `simulation_runs` 增加来源判别列 `source ∈ {SMOKE, LIVE}`，probe 与 live 可在 SQL 层区分，不再依赖场所命名约定 | 列存在且带 CHECK；`select source, count(*) group by source` 可分别计数 |
| G02-R02 | `run_simulation_smoke` 产出的每条 run 标记 `SMOKE`；连续观察循环产出的标记 `LIVE`；来源由**调用方显式传入**，不由引擎猜测 | 实跑烟测后新增 run 的 `source='SMOKE'`；`run_simulation_run` 的每个调用点显式传参 |
| G02-R03 | 存量回填：迁移时刻已存在的每一行都是探针行 | 回填后 `smoke_runs` 等于迁移前行数、`live_runs = 0` |
| G02-R04 | 回填**不得削弱**既有的不可变保护 | `simulation_runs_immutable`（`0005` 的 `BEFORE UPDATE OR DELETE`）在迁移前后均存在且仍然生效 |
| G02-R05 | 概览接口透出来源构成（`smoke_runs` / `live_runs`），供界面区分 | 两个计数字段随概览返回且与 SQL 直查一致 |
| G02-R06 | 界面必须让来源一眼可辨：统计卡顶部的来源提示、机会历史列表每行的来源徽章、单 run 详情页来源徽章 | 来源提示文案区分「全探针 / 全实时 / 混合」三种情形；列表行显示「合成簿」或「实时」 |
| G02-R07 | 烟测入口与日志必须自我说明是合成数据，不得被读成市场模拟 | 按钮文案为「运行合成簿烟测」并附说明文字；`run_simulation_smoke` 首行打出 `SYNTHETIC FIXTURES … not market data` |
| G02-R08 | 实时 run 为 0 时，界面须解释原因（准入未通过）而非留白 | 来源提示文案含「实时 run 0 条 —— 准入未通过（凭证/资格未配置，见控制台账户状态）」 |
| G02-R09 | 模拟页的合约过滤保持**页内独立**（不接管全局「聚焦币种」），且选项值必须与库中存储值一致 | 8 个配置币对均可选，选中返回精确匹配结果；不改 `ConfigStrip` 语义 |
| G02-R10 | 不改动任何撮合/准入/补偿语义；不引入真实或测试网订单路径；`external_order_calls=0` 恒真 | 既有 192 core + 8 tauri-lib 测试不回归；烟测仍断言 `external_order_calls=0` |

## 3. 正常、边界、失败与恢复场景

| 场景 | 输入 | 必须观察到 |
|---|---|---|
| 正常 | 运行一次烟测 | 新增 run 全部 `SMOKE`；界面来源提示显示探针计数增加 |
| 正常 | 实时循环交入 accepted 机会 | 该 run 为 `LIVE`；来源提示切换为「实时 N 条」或「混合」 |
| 边界 | 库中只有探针数据 | 提示为警示态并说明实时为 0 的原因 |
| 边界 | 库中只有实时数据 | 提示为正常态（`smoke_runs = 0`） |
| 边界 | 空库（0 行） | 不显示来源提示（无数据无可判别） |
| 失败 | 迁移在不可变保护下试图 UPDATE 既有行 | 迁移必须整体回滚且不留残迹（sqlx 每文件一事务） |
| 失败 | 已应用迁移文件被改动 | 沿用 MIG-01 的校验和硬失败 |
| 恢复 | 迁移失败后重跑 | 无 `Dirty` 残留，修正迁移文件后可直接重跑（因失败行与其记账同事务回滚） |

## 4. 明确不做

- **不改烟测的 symbol 取值**。探针跑的是合成簿，把 `"BTCUSDT"` 改成观察中的币对属伪造来源；正确做法是标注来源（本迭代）而非改标签。
- **不接管全局「聚焦币种」**。所有者明确选择「模拟页保持独立过滤」；`ConfigStrip` 的 tooltip 与语义不动，模拟页继续用它自己的合约筛选。
- **不让概览聚合随合约筛选变化**。模拟页的合约筛选作用于机会历史列表（筛选控件本就在该面板上）；统计卡/曲线/山脊/流转仍为全量，由来源提示负责解释口径。
- **不新增实时 run**。实时 run 为 0 是准入失败关闭的正确结果，本迭代不降低任何准入阈值去制造 run。
- **不为探针数据增加清理/归档**。已有 620 条探针行保留作历史记录，`source` 列使其可被区分与将来单独清理。
- **不引入 `sqlx migrate` CLI、不改 MIG-01 的记账机制**。
