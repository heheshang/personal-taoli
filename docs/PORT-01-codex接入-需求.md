# PORT-01 codex 接入：需求文档

文档状态：**待所有者确认**（2026-09-10）。立项编号 **PORT-01**，与 `DB-01`、`PERF-01`、`MIG-01`、`UI-01` 同为**段外特批的横切迭代**（不占用 A–G 业务阶段编号，§11 下一轮唯一业务入口不变）。

**流程偏差声明（必须记录）**：所有者指令为「精读 codex 相关代码，将 codex 移植到本项目中」。AI 已完成精读取证（见设计文档 §1），并在精读中发现「全量移植」在工程量上不成立（实测 1,303,294 行非测试 Rust，为本项目 Rust 总量的 **64 倍**），同时发现一条所有者未提及的既有能力路径（`codex app-server` 动态工具注入 + 自定义审批）。因此本迭代**未按字面「移植源码」展开**，改为提交三个候选方案并请求所有者在**设计评审门禁**上做前置选择。按手册 §5.5，本迭代在所有者指定方案前不得进入实现；需求/设计/任务三份文档均为**待确认草案**。

**与架构文档的一致性**：`docs/个人加密货币套利系统-架构与需求设计.md` §1.2 明确「**AI/LLM 直接决策和下单 — 不采用**；核心路径必须可解释、确定、可回放；可用于离线分析和报告」。本迭代的全部需求都限定在该许可范围内，**不触碰任何交易决策路径**。

---

## 1. 目标

本项目是 Rust（`crates/core` 18,836 行 + `src-tauri` 1,447 行）+ Vue 前端（4,983 行）的加密套利观察/仿真系统，已有 99 份过程文档与严格的 AIDLC 门禁（需求 → 分析 → 设计 → 实现 → 验证 → 发布，人工门禁在需求确认、设计评审、发布评审三处）。

`openai/codex` 是一个已在本机安装（v0.154.0）并已登录的生产级 Rust agent harness。本迭代的目标是**把 codex 的 harness 能力接入本项目，用于离线分析与报告**，同时满足三条不可协商的约束：

1. **不进入交易决策路径**（架构文档 §1.2）。
2. **人工门禁不可绕过**（手册 §5.5）——AI 不得自行推进阶段、扩大范围或宣称发布。
3. **可复现证据**（手册 §5.3）——任何 AI 产出的结论必须可追溯到文件、符号、命令、输出。

## 2. 需求

| 编号 | 要求 | 验收结果 |
|---|---|---|
| PORT01-R01 | **能力接入**：以 codex 为 agent 运行时，由**运行时内置工具 + 已配置 skill** 提供能力；宿主注册自定义工具的机制须可用，但当前不注册（原工具作用域错误，已移除） | 工具的注册/广告/分发/未注册即拒全链路可用且有测试覆盖（以测试工具验证）；未注册的工具不可被调用；trace 可按名归因每次调用 |
| PORT01-R02 | **人工门禁**：所有会产生副作用的动作（命令执行、文件变更、权限扩张）必须先经所有者审批，且审批决策可持久化审计。**实现约束（实测）**：仅设只读沙箱不足以产生审批流量，宿主必须显式配置 `approvalPolicy = "untrusted"` | 未审批的动作不执行；审批请求与决策成对落盘；审批超时按失败关闭（不自动放行）；**拒绝不可被重试绕过**；不得存在「本会话内不再询问」或策略修订式的长期放行 |
| PORT01-R10 | **操作档位**：提供与 Codex 桌面版一致的三档——**请求批准 / 帮我批准 / 完全访问权限**（所有者指令）。每档是一组设置的**合取**：运行时的 sandbox、approvalPolicy、approvalsReviewer，以及本项目自己的沙箱形状。会话运行中不得改档 | 三档标签与说明逐字取自 app 语言包；每档的运行时设置与自有沙箱实测与其标签一致（见任务文档 PORT-01-L 的实测表）；未知 token 被拒而非回退；改档在会话运行中被拒并给出可操作原因 |
| PORT01-R09 | **子进程受限**：agent 运行时进程的可写范围由本项目自有的 macOS Seatbelt 策略限定（其 home 与 trace 目录），**不含工作区**；沙箱不可用时拒绝启动，不得退回未受限运行 | 子进程越界写入被拒（附真实拒绝输出）；授权范围内写入成功；受限后子进程仍能完成握手；沙箱不可用时启动返回错误而非成功 |
| PORT01-R03 | **只读边界**：接入进程不得持有交易密钥、不得调用下单/撤单/划转路径、不得写入 `crates/core` 的账务与订单事实表 | 接入模块的依赖图中不存在任何 `order`/`execution`/`account` 的写函数；进程环境变量不含 `TAOLI_BINANCE_API_SECRET`/`TAOLI_BYBIT_API_SECRET`（在**启用沙箱前的探测**中验证） |
| PORT01-R04 | **可复现**：每次会话的 thread/turn/工具调用/审批决策全量落盘，可按 thread id 回放，用于归因 | 给定 thread id 能还原完整调用链（含工具入参与逐字出参、审批裁决及其来源、被拒请求）；回放同一文件两次结构相同；结构性损坏（乱序/坏行/未结束会话）必须报错或如实标记为未结束，不得表现为成功 |
| PORT01-R05 | **领域指令注入**：向 agent 注入本项目领域约束（只读边界、数字以工具返回为唯一权威、Decimal 以字符串逐字引用、失败关闭、单轮单闭环、不确定显式标注），且指令随代码版本管理 | 注入内容**逐字**来自仓库内受版本控制的 `docs/agent/instructions.md`；该文件缺失或为空时**拒绝启动**（不得退回无约束运行）；不在代码中硬编码；trace 记录当时生效的指令指纹 |
| PORT01-R06 | **不改变既有行为**：接入不得修改 `crates/core` 现有公开 API、数据库 schema 或前端契约 | `cargo check --workspace --all-targets` 通过；现有迁移文件逐字未变；前端 `npm run build` 通过 |
| PORT01-R07 | **明确的「不做」清单**：本迭代不引入 codex 的 TUI、不引入 V8 code-mode、不引入 Windows/Linux 沙箱、不移植 codex 源码 | 交付物中不存在上述组件的依赖或拷贝 |
| PORT01-R08 | **裁决对齐 Codex 桌面版，但不允许长期放行**（所有者两次指令的合取）：审批提供**允许一次 / 允许此对话 / 拒绝**，禁用**始终允许**。可用集合由宿主按请求类型、运行时提议与**持久化是否可行**算出；未提供的选项不得被选用 | 三个动作可点且文案与 codex app 一致；每个动作映射到对应词汇并被接受（实测 `completed` / `declined`）；子进程不能写运行时的规则目录（沙箱 carve-out + 越权守卫 + 二者绑定的测试）；界面说明第四项缺席的原因；超时与无裁决通道仍为**拒绝** |

## 3. 正常、边界、失败与恢复场景

| 场景 | 输入 | 必须观察到 |
|---|---|---|
| 正常 | 发起一次只读分析会话 | 审批仅覆盖实际动作；工具结果进入 trace；产物写入约定目录 |
| 正常 | 模型调用已注册的只读工具 | 工具执行并回结果，**不触发审批**（无副作用） |
| 正常 | 模型尝试运行 shell 命令 | 运行时抛出审批请求；宿主持有者裁决；裁决写入审计 |
| 正常 | 会话中模型请求调用了未注册工具 | 请求被拒绝并回错误，不静默降级为内置工具 |
| 边界 | 所有者在截止前未作裁决 | 记 `source = Timeout` 且 `decision = Deny`；动作未执行；不自动放行 |
| 边界 | 会话中途所有者拒绝该动作 | 该动作被标记 declined；agent 收到拒绝结果并可继续；**重试同样被拦** |
| 边界 | 审批裁决在宿主侧无法表达（如对权限扩张的 Allow 无 profile 可回显） | 记为 `source = Unsupported` 并降级为拒绝，不做猜测式放行 |
| 边界 | codex 二进制不存在或版本不匹配 | 启动前检出并给出可操作错误；不得静默降级 |
| 边界 | codex 进程被外部杀死 | 宿主进程不挂起；等待中的审批被清理；会话标记为中断 |
| 失败 | 沙箱不可用（如嵌套 Seatbelt 返回 `Operation not permitted`） | 按失败关闭拒绝执行，而非无沙箱放行 |
| 失败 | 工具返回数据超期（快照年龄超限） | 按 §2.3 失败关闭语义拒绝，不返回过期数据 |
| 失败 | 审计日志无法写入 | 记录错误到日志；裁决结果仍以 `TurnOutcome` 返回，不静默丢失裁决 |
| 恢复 | 宿主重启后要求继续会话 | 凭 thread id 恢复；历史从落盘文件重建；不得凭内存状态推测 |

## 4. 明确不做（本迭代范围外）

- 移植 codex 源码（任何形式的 vendor 或拷贝）。
- 让 AI 参与交易决策、下单、撤单、划转（架构文档 §1.2 禁止）。
- 修改 `crates/core` 的交易/账务/对账逻辑。
- 引入 codex 的 TUI / 桌面端 / V8 code-mode / 云端任务。
- 自动化的 agent 自进化循环（对应《Agent 评测白皮书》的 L3，本迭代不涉及）。
