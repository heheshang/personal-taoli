## 3. 启动

在具备进程监督和失败自动重启的环境中运行：

```bash
target/release/personal-taoli \
  --config config/observer.toml \
  --archive data/archive/a05-shadow-20260908.ndjson \
  --quiet
```

启动成功的 stderr 必须同时出现：

```text
OBSERVE mode: ... no orders
ARCHIVE path=data/archive/a05-shadow-20260908.ndjson gaps=data/archive/a05-shadow-20260908.ndjson.gaps.ndjson
```

监督器必须保留启动时间、退出码、信号和重启次数。当前工作站由受管进程 `taoli-shadow-a05` 监督；故障退出自动重启。不要用未经监督的后台 shell 进程代替正式窗口。

## 4. 日常在线核对

在线回放不会阻塞写入器，只读取命令启动瞬间的完整文件长度：

```bash
target/release/personal-taoli \
  --replay data/archive/a05-shadow-20260908.ndjson \
  --output json
```

每次核对至少保存或记录：

- `archive_bytes` 和 `records` 持续增长；
- `first_event_at_ms` 不变化，`last_event_at_ms` 前进；
- `replayed_without_mismatch=true`；
- `gap_records`、`dropped_events`；
- `ignored_incomplete_tail_bytes`、`ignored_gap_tail_bytes`；
- `health_records`、`invalid_duration_ms`、双方 `reconnects`；
- 方向评估数、正净收益数、准入数、收益/容量分布、拒绝类别和尾部样本；
- 监督器的 PID、uptime、退出/重启记录。

在线回放偶尔出现非零 `ignored_incomplete_tail_bytes` 可仅表示末行正在写入；下一次回放应回到 0。持续非零、增长或重启修复记录必须调查。

## 5. 停止与恢复

### 5.1 计划停止

向受监督的进程发送 SIGTERM 或 Ctrl-C。程序应输出：

```text
observer stopped; flushing archive
```

退出码必须为 0。停止后立即执行回放并确认：

- `replayed_without_mismatch=true`；
- `ignored_incomplete_tail_bytes=0`；
- `ignored_gap_tail_bytes=0`；
- 没有新增未解释缺口。

### 5.2 非计划退出

1. 先保留监督器退出原因和时间。
2. 自动重启后确认新记录使用新的 `run_id`，新运行的 `ordinal` 从 1 开始。
3. 执行回放。若启动修复了无换行尾部，缺口日志应有 `discarded ... incomplete bytes`，且 `dropped_events=0`。
4. 计算退出前最后事件到重启后首个事件的间隔，并记录为进程停机；不能计入连续在线时间。
5. 若发现完整换行损坏行，不要修改原始文件。复制保全后停止将该窗口作为完整证据，并调查磁盘、并发写入和进程版本。

### 5.3 写入故障

`archive write failed`、`archive gap write failed` 或 `archive submit failed` 均为 P0 观察证据故障。行情扫描继续不代表窗口有效。修复磁盘/权限后执行回放，量化缺口并决定重启新窗口或明确拒绝 A05-R06。

## 6. 14 天连续性核对

最终评审不能只读取 `observed_duration_ms`。按以下顺序核对：

1. **时间边界**：首条事件不早于正式起点；末条事件不早于 2026-09-22T09:52:14Z。
2. **原始顺序**：回放成功，所有运行内序号严格递增，事件时间无倒退。
3. **运行边界**：列出归档中所有 `run_id` 及各自首末时间、首末序号；与监督器重启记录逐一对应。
4. **采样连续性**：配置周期为 2 秒。计算相邻记录时间差；任何显著超过 `poll_interval_ms` 的间隔都要与行情健康事件、账户刷新、进程停止或主机休眠对应。不得把无事件停机误算为在线。
5. **主机/监督器连续性**：核对 uptime、退出码、重启次数和宿主机睡眠/重启。不能解释的停机使“连续 14 天”门禁失败。
6. **数据完整性**：归档和缺口日志均无未完成尾部；`gap_records=0`、`dropped_events=0`。若非零，逐条调查并说明是否必须重开窗口。
7. **行情恢复样本**：Binance 与 Bybit 的自然重连计数各至少增加 1，且至少有一次 `HealthEvent` 后恢复为双方 `VALID` 的决策事件；主动 `--reconnect-smoke` 不计入。
8. **独立机会样本**：按归档顺序分别跟踪两个方向。`expected_net_profit > 0` 从非正值转入，或与同方向上一条正值样本相隔至少 30 秒时，新计一个独立正净收益候选事件段；持续正值段只计一次。两个方向合计至少 100 个并分别报告，不能用方向评估数、连续采样数或 `accepted_opportunities` 替代。

当前实现不会直接输出最大相邻事件间隔或运行清单。最终评审可使用只读脚本分析 NDJSON，但脚本、命令、输出摘要和判定必须随评审记录保存；不得改写原始归档。
