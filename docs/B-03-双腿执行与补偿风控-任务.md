## 2. 必须通过的行为

1. 两腿成交量差使用 `Decimal` 计算并可从数据库恢复。
2. 敞口和累计补偿成本在各自上限内时只生成 `COMPENSATION_PLANNED`，不宣称已补偿。
3. 敞口或补偿预算超限时进入 `MANUAL_REQUIRED`，保留数量、成本、原因和版本。
4. 两腿后续匹配后进入 `COMPLETED`；终态不可重复评估。
5. 计划超量或成交倒退不能静默覆盖事实。
6. 域锁阻止同一账户—品种的第二写者。
7. 烟测外部订单调用固定为 0。

## 3. 发布阻塞

- 任何真实/测试网订单、撤单、私有流或真实凭证要求。
- 将补偿计划直接当作补偿订单成功。
- 未知订单未经过 B-02 调查即按零成交评估。
- 敞口/预算超限后继续自动补偿。
- PostgreSQL 事实、事件、决定或恢复无法通过实际烟测。
- A-05 连续观察门槛未满足；本轮即使验证通过也不能进入真实订单适配器。
