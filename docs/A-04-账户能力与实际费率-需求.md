# A-04 账户能力与实际费率：需求文档

## 1. 文档状态

- 迭代编号：A-04
- 状态：`released`
- 发布日期：2026-09-08
- 目标：以可审计能力卡、只读账户权限和账户实际 taker 费率替代仅靠配置假设的准入
- 上游依赖：A-03 已提供公共实时本地订单簿
- 下游依赖：A-05 将账户版本与每次影子决策一并归档

## 2. 范围

### 2.1 本轮必须实现

1. 为 Binance 与 Bybit 输出场所能力卡和官方资料来源。
2. 只从配置命名的环境变量读取 API key/secret，且仅调用私有只读接口。
3. 核验读取权限、交易/提现等危险权限以及地区/账户资格人工确认。
4. 获取当前 symbol 的账户实际 taker 费率，区分买卖侧并记录加载时间、过期时间和来源。
5. 凭证缺失、权限不安全、资格未确认、接口失败或费率过期时继续公共观察，但所有机会失败关闭。
6. 支持独立账户检查和持续模式定期刷新。
7. 输出和错误不得包含 API key、secret 或签名负载中的秘密值。

### 2.2 明确不做

- 不创建、修改、查询或撤销订单；能力卡中的交易接口语义只是未来设计资料。
- 不读取或展示资产余额、持仓、地址或资金流水。
- 不自动判断法律资格；地区与账户资格必须由用户基于实际情况显式确认。
- 不把配置回退费率视为实际账户费率，不允许其通过经济准入。
- 不自动撤销危险 API scope，也不修改交易所 API key 设置。
- 不承诺 API key IP 限制已启用；只记录交易所返回状态供人工审核。

## 4. 准入规则

账户数据用于“是否允许机会进入未来执行候选”的硬门禁，不影响公共盘口观察。任一场所出现以下任一条件时，两个方向都必须拒绝：

1. `region_eligible_confirmed != true`；
2. `account_eligible_confirmed != true`；
3. API key/secret 缺失或不完整；
4. 私有权限接口失败或响应不可解析；
5. `permission.read_only != Some(true)`；
6. Binance 存在任何已识别危险 scope，或 Bybit 存在提现权限；
7. 账户实际费率未取得，仍在使用配置回退；
8. 实际费率已超过 `expires_at_ms`；
9. 实际费率不在 `[0,1)`。

`ip_restricted` 必须输出以供审计，但当前实现不自动把它作为准入门禁。若要升级为硬门禁，必须修改需求、实现和验收，不得只改文档表述。

## 5. 凭证与签名需求

### 5.1 注入

每个场所由配置给出 `api_key_env`、`api_secret_env`。程序只能读取对应环境变量：

- 两项均不存在：记录“未配置只读凭证”；
- 仅一项存在：记录“凭证不完整”；
- 两项均存在：才允许发起私有只读请求；
- 环境变量名不得为空，两个配置项不得相同。

### 5.2 Binance

- 请求头：`X-MBX-APIKEY`；
- 签名：对 URL query bytes 做 HMAC-SHA256，十六进制小写；
- query 含有配置限制内的 `recvWindow` 和本机毫秒时间戳；
- 权限接口：`/sapi/v1/account/apiRestrictions`；
- 费率接口：`/api/v3/account/commission?symbol=...`；
- 买侧使用 `takerCommissionForOrder` 的 `buyer + taker`，卖侧使用 `seller + taker`。

### 5.3 Bybit

- 请求头包含 `X-BAPI-API-KEY`、`X-BAPI-TIMESTAMP`、`X-BAPI-RECV-WINDOW`、`X-BAPI-SIGN`；
- HMAC-SHA256 payload 为 `timestamp + api_key + recv_window + query`；
- 权限接口：`/v5/user/query-api`；
- 费率接口：`/v5/account/fee-rate?category=spot&symbol=...`；
- 只有 `retCode == 0` 才接受响应，费率使用 `takerFeeRate`。

## 6. 数据需求

### 6.1 `CapabilityCard`

必须包含：

- 地区资格和账户资格人工确认值；
- order recovery、限频、client order ID、IOC/FOK、费用币种、历史窗口说明；
- 对应官方来源 URL 列表。

### 6.2 `PermissionAssessment`

必须包含：

- `configured`；
- `read_only: Option<bool>`；
- `ip_restricted: Option<bool>`；
- 已启用 scope 列表。

未实际查询时 `read_only` 和 `ip_restricted` 为未知，不得默认为安全。

### 6.3 `FeeSchedule`

必须包含：venue 对应 symbol、买侧 taker、卖侧 taker、来源、`loaded_at_ms`、`expires_at_ms`、`actual_account_rate`。回退费率不伪造加载/过期时间，且 `actual_account_rate=false`。

## 7. 失败与降级

| 场景 | 观察行为 | 准入行为 |
|---|---|---|
| 无凭证或凭证不完整 | 公共行情继续；输出回退费率与原因 | 两方向拒绝 |
| 地区/账户资格未确认 | 公共行情和账户查询可继续 | 两方向拒绝 |
| 单所私有接口错误 | 另一所结果保留；失败所回退 | 两方向拒绝 |
| 权限非只读 | 输出启用 scope | 两方向拒绝 |
| 费率过期 | 保留最后费率版本供解释 | 两方向拒绝 |
| 返回费率非法 | 将加载视为失败并回退 | 两方向拒绝 |
| 持续刷新失败 | 用当轮新构造的失败侧数据和拒绝原因替换旧版本 | 两方向拒绝，不继续信任旧成功费率 |

选择“刷新失败即撤销旧成功准入”，避免暂时网络故障期间无限沿用无法证明仍有效的账户费率或权限。

## 8. 非功能需求

- **最小权限**：只调用权限与费率读取接口；程序没有订单能力。
- **秘密生命周期**：凭证字符串用 `Zeroizing` 持有，离开作用域清零；不进入可序列化结构。
- **失败关闭**：任何未知状态都归为拒绝，而不是按安全推断。
- **并行独立**：两所查询并发执行，单所故障不掩盖另一所实际结果。
- **时间有界**：HTTP timeout、recvWindow、刷新周期和最大费率年龄均由验证后的配置控制。
- **精确计算**：费率以 `Decimal` 解析，不使用二进制浮点。
- **可审计**：来源、加载/过期时间、permission scopes 和拒绝原因均可输出并由 A-05 归档。

## 9. 验收与发布证据

发布验证覆盖：

- Binance 官方签名向量；
- Binance 买卖侧 commission 分量组合；
- Binance 权限和危险 scope 判定；
- Bybit 请求签名与错误归一化；
- Bybit `readOnly` 和提现权限解析；
- 实际费率过期边界；
- 费率参与双向扫描的场所/买卖侧映射；
- `cargo fmt --all -- --check`、测试和 Clippy 严格模式；
- 无凭证 `--account-check --output json` 真实运行。

本机发布环境没有提供两所真实账户凭证，因此签名与响应解析由确定性本地 HTTP 夹具验证，真实账户权限和实际费率仍是上线前待验证项。该限制不会被“released”掩盖：A-04 发布的是安全只读能力与失败关闭逻辑，不是账户已获准实盘。

## 10. 发布判定

A04-R01 至 A04-R09 已实现并于 2026-09-08 发布。只要真实账户凭证尚未完成核验，系统必须继续显示对应拒绝原因且不能满足实盘准入。
